# 관리자 관리 이미지 분석 동시 수 (2026-10-22)

## 사용 방법

- 사용자 화면의 1~20건 선택창을 제거했다. `최대 동시 분석 N건 · 관리자 설정`만 읽기 전용으로 표시한다.
- 기본값은 **3건**이다. 관리자 페이지 → AI 및 서버 제어판 → `이미지 분석 동시 수 설정`에서 **1~20 사이의 정수**를 저장한다. 기존 AI 서버/모델 설정을 바꾸지는 않는다.
- 브라우저는 모달을 열 때와 새 요청 묶음/실패 재시도를 시작하기 전에 최신 정책을 조회한다. 정책 조회 실패/잘못된 응답일 때 임의 값으로 분석을 시작하지 않는다.

## 서버 적용과 저장

- 기존 `admin_ops_control_settings` 저장소의 `image-analysis.max-concurrent` 키를 사용한다. 관리자 운영 설정 서비스가 기존처럼 준비하는 테이블이며 신규 DB 마이그레이션은 없다.
- 설정 저장 실패는 오류로 반환한다. 트랜잭션 커밋 후 실행 풀에 적용하고 롤백 시 실행 풀은 변경하지 않는다. 재시작 후 저장값을 다시 읽는다.
- 이미지 실행 풀을 저장값에 맞춰 조절하고, 공유 DB 작업 lease로 이미지 추론 슬롯을 확보해 여러 사용자·브라우저·서버 인스턴스의 호출도 제한한다. 업로드를 직접 호출하거나 이력을 재요청해도 동일한 서버 한도를 거친다.
- 설정은 시작/조회 시와 5초 주기로 갱신한다. 한도를 낮출 때 이미 실행 중인 작업은 강제 종료하지 않고 완료되도록 두므로 전환 중에는 이전 작업이 새 한도를 일시적으로 초과할 수 있다. 새 브라우저 요청 묶음부터 최신 개수를 사용한다.
- `LEDGER_OCR_WORKERS`는 초기 풀 크기이며 실행 중 관리자 설정이 우선한다. 예전 환경변수에 6이 남아 있어도 관리자 설정이 없으면 3으로 조정된다. Java·YAML·Compose·환경변수 예제 초기값도 3으로 통일했다.
- 제공자 공통 상한(`APP_LEDGER_AI_MAX_CONCURRENT`)은 별도로 유지한다. 더 낮은 제공자 상한은 그대로 적용된다. 단일 GPU는 관리자 이미지 동시 수와 제공자 공통 상한을 모두 1로 설정한다. 사용자별 접수 수/큐 용량은 병렬 실행 수와 다른 제한이며 기존 20/100을 유지한다.
- 일반 사용자용 `GET /api/ledger/image-analysis/settings`는 숫자 정책만 반환한다. 관리자용 `GET/PATCH /api/admin/ops-control/image-analysis`는 ADMIN 역할·기존 2차 인증을 요구하며 변경에는 CSRF와 입력 검증을 적용한다. 변경값은 감사 로그에 남긴다.
- 브라우저 빌드의 `VITE_LEDGER_IMAGE_CONCURRENCY`와 일반 사용자의 직접 선택은 더 이상 사용하지 않는다.

## 검증

- 프런트 단위 테스트 46건 및 빌드 통과.
- PC·모바일 모의 API 44개 시나리오 확인: 기본 3건·관리자 정책 변경·설정 실패 시 미전송·기존 병렬 처리/검수·관리자 입력/저장/재진입. 마지막 전체 실행의 42건 통과 후, 건수가 포함된 재시도 버튼 이름으로 테스트 선택자를 보정하고 나머지 PC·모바일 2건도 재실행 통과했다. 정책 조회 실패 후에도 이미지별 원래 요청사항이 재시도에 유지됨을 확인했다.
- 백엔드 대상 테스트 79건 통과. 격리 H2로 설정 저장·재시작 로드·롤백·공유 슬롯 3건·실패/취소 슬롯 반환을 확인했다.
- Spring 보안 검사로 비로그인/일반 사용자 차단, 관리자 2차 인증/CSRF, null·0·음수·21·소수 거절, 감사 로그를 확인했다. 실제 Spring 애플리케이션 구성에서도 H2 기반 인증·저장·조회가 통과했다.
- 환경변수 동기화·AI 제공자 안전 계약·변경 파일 공백 검사 통과. 관리자 화면 PC·모바일 테마별 캡처 확인.
- 운영·VM 배포·실제 AI 호출은 하지 않는다. 커밋·푸시는 별도 요청 시 진행한다.
