# AI 이미지 분석 목록·렌더링 개선 (2026-10-21)

## 재현 및 원인

- 이미지 6장(같은 파일명 포함)을 선택하고 3장의 분석만 완료시킨 모의 검사에서, 실제 카드 수가 6개에서 3개로 줄었다. `receiptAnalyzeItems`가 `status === 'done'`인 이미지를 목록에서 제외하고 있었다. 서버가 3장만 받았다는 증거는 아니며, 프런트 표시 문제를 재현한 결과다.
- 분석이 모두 끝나면 자동으로 이력 탭으로 이동하면서 현재 작업 목록·진행 수치도 사라졌다.
- 한 이미지에 거래 후보 83건이 있으면 입력 폼 83개를 동시에 렌더링했다. 각 폼에는 분류·결제수단 선택지, 입력칸, 메모 등이 반복된다.
- 전역 모달 감시가 일반 표/지도/펫의 클래스 변경에도 전체 문서에서 모달을 다시 검색했다. 데스크톱에서도 모바일 전용 스크롤 잠금을 위해 문서를 검색하고 있었다.

## 변경

- 현재 선택/요청 묶음의 이미지 ID를 별도로 보관한다. 완료·진행·대기·실패·취소 상태와 무관하게 같은 묶음의 카드를 유지하며, 상태별 건수를 표시한다.
- 일괄 분석 완료 시 탭을 강제 전환하지 않는다. 이력은 계속 갱신하며, 사용자가 이력 탭에서 확인할 수 있다. 새 파일 선택 시 이전 완료 묶음은 현재 목록에 섞이지 않는다.
- 분석 중 재요청으로 현재 묶음이 덮어써지지 않도록 막고, 단일 재요청·기존 직접 분석 경로도 묶음 진행 수치를 초기화한다.
- 이미지별 거래 검수 폼을 10건씩 렌더링한다. 원본 배열과 거래 인덱스는 유지하므로 페이지 전환 후에도 수정 내용·입력칸 적용·승인 대상 번호는 바뀌지 않는다. 83건 사례의 동시 폼은 83개에서 최대 10개로 줄었고 마지막 페이지는 3개다. 데이터 자체를 잘라내지는 않는다.
- 페이지별 데이터 계산을 캐시하고, 미리보기 이미지는 지연 로딩/비동기 디코딩한다. 화면 밖 카드의 레이아웃·페인트도 브라우저가 건너뛸 수 있도록 한다.
- 모달 감시는 추가/제거/속성 변경이 실제 모달 또는 전체화면 지도 상태와 관련 있을 때만 동기화한다. 일반 클래스 변경에는 문서 전체 모달 검색을 하지 않으며, 데스크톱은 모바일 검사 전에 반환한다.

## 로컬 검증 범위

- 프런트 빌드 성공.
- 단위 테스트 31건 통과: 6장 상태 변화·같은 이름·제거·기존 묶음 격리, 거래 페이지 경계/원본 인덱스/수정 참조 유지, 모달 추가·제거·전체화면 상태 변화 및 불필요한 감지 방지 포함.
- 모의 API 브라우저 검사(PC·모바일) 6건 통과: 6장 선택 후 3장 완료 상태에서도 카드 6개 유지, 비동기 완료 상태 조회, 중간 1건 실패 후 나머지 진행, 6개 단일 이미지 요청 확인, 재선택 후 기존 묶음 격리, 라이트·다크 페이지 전환 시 편집 보존, 83건 분할 검수와 83번째 거래의 입력칸 적용/원본 인덱스 보존, 일반 DOM 갱신 시 전체 문서 모달 검색 0회, 닫기 후 모바일 스크롤 잠금 복구를 확인했다.
- 기존 가계부·거래 시트·집계/빠른 입력 제목·화면 회전/수동 배치 선택의 모의 회귀 검사 21건도 통과했다. 실행: `node node_modules/@playwright/test/cli.js test --config playwright.aggregate-header.config.js --grep "aggregate header|quick entry header|ledger controls|automatic mode"`.
- 실제 AI 호출/운영 데이터/VM 배포는 사용하지 않았다. 따라서 서버 추론 시간이나 운영 환경의 모든 느린 페이지가 개선됐다는 의미는 아니며, 이번에 재현한 표시·렌더링 문제의 수정 범위다.

실행: `npm run test:unit`, `npm run build`, `node node_modules/@playwright/test/cli.js test --config playwright.receipt-analysis.config.js`.
