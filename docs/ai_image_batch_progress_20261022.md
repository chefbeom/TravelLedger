# 이미지 분석 요청 묶음 진행률 및 완료 후 자동 갱신 (2026-10-22)

## 동작

- 분석을 시작하면 모달 상단에 `요청 처리 0 / 10건`, 진행 막대, 백분율을 표시한다. 각 이미지가 완료·실패·취소 상태가 될 때 처리 건수를 갱신한다.
- 성공 완료·실패·취소·남은 요청 수를 구분한다. 실패나 취소도 처리 종료에는 포함하지만 성공으로 표시하지 않는다. 대기 중인 이미지를 제거해도 원래 요청 묶음의 전체 건수는 줄지 않는다.
- 진행 정보는 현재 요청 묶음만 집계한다. 과거 결과나 분석 도중 새로 선택한 초안이 전체 건수를 바꾸지 않으며, 이미 끝난 요청의 결과는 목록에서 제거해도 재분류하지 않는다.
- 이력 탭으로 이동해도 상태바를 유지한다. 모달을 닫아도 기존 순차 분석은 계속되고 다시 열면 현재 상태를 볼 수 있다.
- 한 묶음의 처리가 끝나면 성공 여부와 관계없이 이력 첫 페이지와 검수 대기 건수를 자동 조회한다. 전체 페이지를 재로딩하거나 검수 탭으로 강제 전환하지 않아 선택한 이미지와 편집 내용은 유지된다.
- 완료 후 갱신은 HTTP 캐시 및 진행 중 GET 병합을 사용하지 않는다. 이전 조회의 늦은 응답이 최신 이력이나 요약을 덮어쓰지 않도록 조회 순서를 확인한다.
- 갱신 실패는 분석 실패와 구분해 표시한다. `새로고침 재시도`는 이력과 대기 건수만 다시 조회하며 AI에 이미지를 다시 보내지 않는다.
- 단일 이미지 재요청에도 같은 진행률 및 완료 후 갱신 처리를 적용한다.
- 모바일에서는 상단 제목·닫기와 탭 배치를 압축해 진행 상태바가 검수 버튼의 사용 공간을 빼앗지 않도록 했다.

## 변경하지 않은 부분

- 이미지별 단일 POST·순차 분석·비동기 결과 폴링 방식은 그대로다.
- AI 프롬프트, 결과 내용, 승인/거래 등록 규칙, 요청 묶음 식별 형식은 바꾸지 않았다.
- 이번 변경으로 백엔드 코드나 DB 스키마는 수정하지 않았다. 앞선 작업의 미커밋 변경은 보존했다.

## 검증

- `npm run test:unit`: 37건 통과. 0/10 → 1/10 → 완료·실패·취소를 포함한 10/10 집계를 확인했다.
- `npm run build`: 통과.
- 모의 API PC·모바일 검증 22건 통과: 10건의 단계별 진행, 이력/배지 자동 조회, 페이지 재로딩 없음, 전부 실패, 대기 요청 제거, 조회 실패 후 재시도, 이전 요약 조회 지연을 검사했다.
- 기존 요청 묶음 표시·배지·6장 선택·83건 분할 검수·입력칸 적용·모달 스크롤 검사도 포함한다. 모바일 검수에서 추가 상태바로 인해 발생한 버튼 가림을 수정하고 재검사했다.
- 운영·VM·실제 AI 서버는 사용하지 않았다. 커밋·푸시는 별도 요청 시 진행한다.
