# 이미지 분석 병렬 요청 큐 (2026-10-22)

> 이후 변경: 기본 6건 및 사용자 선택 UI는 `ai_image_admin_concurrency_20261022.md`의 관리자 정책(기본 3건)으로 대체되었다. 아래 내용은 최초 병렬화 구현 당시의 기록이다.

앞선 이미지 분석 표시/진행률 작업 문서의 순차 처리 설명은 이번 변경으로 대체된다.

## 구현

- 이미지별 단일 요청은 유지하되 순차 반복문을 제한된 병렬 큐로 변경했다. 기본 6건을 먼저 전송하고 한 건이 끝나면 다음 대기 이미지를 시작한다.
- 화면에서 동시 요청 수를 1~20건으로 선택할 수 있다. 실행 중에는 변경을 막으며, 비동기 POST의 `PROCESSING` 응답 이후 최종 결과 폴링까지 한 슬롯을 점유한다. 업로드 접수만 끝났다고 슬롯을 조기에 반환하지 않는다.
- 공통 요청 묶음과 이미지별 고유 `clientRequestId`는 유지한다. 응답 순서와 관계없이 각 요청의 원래 항목에 반영하고, 완료된 카드부터 검수할 수 있다.
- 한 이미지의 실패는 해당 카드에만 반영한다. 다른 작업과 대기 큐는 계속 처리하고 완료·실패·취소 진행률 및 전체 종료 후 자동 갱신을 유지한다.
- `실패 건만 재시도`와 개별 `실패 재시도`를 추가했다. 실패한 로컬 원본만 새 요청 ID로 보내며, 성공 카드와 사용자 수정 내용은 유지한다. 처음 전송한 프롬프트·기존 입력 참고 옵션·기준 날짜도 보존한다. 서버의 이전 실패 이력은 삭제하지 않는다.
- 성공 여부가 불분명한 요청을 무제한으로 자동 재전송하지 않는다. 사용자가 실패 항목을 명시적으로 재시도한다. 저장된 원본만 있는 이력은 기존 상세 화면의 재요청 기능을 그대로 사용한다.
- CSRF 토큰이 없을 때 동시 POST가 각자 토큰을 발급받지 않도록 최초 조회를 합쳤다. 완료 후에는 토큰을 별도로 캐시하지 않아 이후 쿠키 교체도 반영한다.
- 분석 결과 폴링에도 개별 AbortController를 유지한다. 한 항목을 제거하거나 취소해도 다른 요청은 중단하지 않는다.

## 백엔드 및 배포 설정

프런트만 병렬화해도 기존 기본값(이미지 워커 1, 사용자별 접수 5, 제공자 동시 추론 1)이 남으면 실제 AI 호출은 순차 처리되거나 6번째 접수가 거절된다. 다음 값을 Java 기본값, application.yml, 일반/OCI Compose 및 두 환경변수 예제에 동기화했다.

| 설정 | 기본값 | 의미 |
| --- | ---: | --- |
| 화면 동시 요청 수 | 6 | 현재 브라우저의 활성 이미지 작업 수. 최종 결과 폴링까지 포함 |
| `LEDGER_OCR_WORKERS` | 6 | 인스턴스별 실제 이미지 작업자 수 |
| `LEDGER_OCR_MAX_PENDING_PER_USER` | 20 | 인스턴스별 사용자 접수 제한 |
| `LEDGER_OCR_QUEUE_CAPACITY` | 100 | 인스턴스별 대기 큐. 기존 값 유지 |
| `APP_LEDGER_AI_MAX_CONCURRENT` | 20 | 기존 제공자/기본 URL별 공유 추론 상한. 다른 AI 기능과 공유 |

- **상한 20은 사용자가 제시한 AIConnect 구성 기준이다.** 로컬 단일 GPU 환경은 `LEDGER_OCR_WORKERS=1`, `APP_LEDGER_AI_MAX_CONCURRENT=1`, 화면 동시 요청 1건을 사용한다. AIConnect 외부 API의 별도 RPM/TPM·비용·응답 시간 제한을 없애는 변경은 아니다.
- 기본 설정의 이미지 병렬 실행은 6건이다. 실제 이미지 분석을 20건까지 실행하려면 리소스를 확인한 뒤 이미지 워커도 20으로 올리고, 화면에서 20건을 선택한다. 사용자별 접수와 제공자 상한도 그 이상이어야 한다. 여러 사용자/인스턴스는 공유 추론 상한을 나누어 사용한다.
- **운영 환경변수에 과거 값 `1` 또는 `5`가 명시돼 있으면 그 값이 새 기본값보다 우선한다.** 실제 배포 시 `.env`/Jenkins 환경의 위 세 변수를 확인하고 백엔드 컨테이너를 재생성해야 한다. 예제 파일 변경만으로 실행 중인 설정이 바뀌지는 않는다.
- 프런트 직접 빌드는 선택적으로 `VITE_LEDGER_IMAGE_CONCURRENCY`로 초기값을 정할 수 있다(1~20, 잘못된 값은 6). 기본값과 화면 선택만으로도 사용 가능하며, 루트 Compose 환경변수가 Vite 빌드 인수로 자동 전달되는 것은 아니다.
- DB 마이그레이션, 이미지별 저장 및 승인/거래 등록 규칙은 변경하지 않았다.
