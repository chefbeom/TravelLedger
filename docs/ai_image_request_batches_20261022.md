# 이미지 분석: 최대 5건 요청 묶음 (2026-10-22)

## 동작

- 동시 실행 수는 기존 관리자 설정을 그대로 사용한다. 현재 기본값은 3건이며, 사용자가 분석 화면에서 변경하지 않는다.
- 한 번 선택한 이미지가 많아도 최대 **5건씩** 나누어 요청한다. 12장을 선택하면 **5건 → 5건 → 2건**으로 자동 처리한다.
- 각 묶음 안에서는 관리자 설정 수만큼 동시 실행한다. 현재 설정 3이면 3건을 먼저 실행하고, 완료된 자리에 같은 묶음의 나머지 이미지를 투입한다.
- 현재 묶음의 모든 항목이 완료·실패·취소로 정리된 다음에만 다음 묶음을 시작한다. 업로드 접수 응답뿐 아니라 비동기 결과 조회가 끝날 때까지 실행 자리를 유지한다.
- 다음 묶음마다 관리자 정책을 다시 조회한다. 정책 조회에 실패하면 남은 이미지를 임의 설정으로 전송하지 않는다. 서버의 기존 공유 동시성 제한은 변경하지 않는다.
- 관리자 설정이 5보다 크더라도 이번 선택의 한 묶음은 5건이므로 동시에 실행되는 수는 그 묶음의 남은 이미지 수를 넘지 않는다. 관리자 설정값을 5로 덮어쓰거나 낮춰 저장하지 않는다.

## 표시와 재요청

- 진행률은 전체 선택 건수를 기준으로 유지하며, 진행 중인 묶음 번호·전체 묶음 수·이번 묶음의 건수를 함께 표시한다.
- 새 요청 이력도 최대 5건 단위의 별도 묶음 ID를 사용한다. 개별 이미지 결과 연결과 순서는 유지한다.
- 실패 항목을 재요청할 때도 최대 5건 단위로 실행하되, 기존 분석 ID·최초 요청 시각·원래 요청 묶음은 바꾸지 않는다. 과거에 생성된 6건 이상 묶음도 기존 모습으로 읽을 수 있다.
- 이미지 하나당 API 요청 하나라는 기존 서버 계약은 그대로다. 여러 이미지를 한 번의 AI 추론 요청에 합치는 변경이 아니다.
- 프런트 요청 분할 및 표시만 변경하며 신규 DB 마이그레이션이나 서버 동시성 설정 변경은 없다.

## 검증

- 단위 테스트: 12건의 5/5/2 분할, 설정 3건 동시 실행, 느린 첫 묶음 대기, 일부 실패 후 다음 묶음 진행, 묶음 사이 정책 갱신, 상한 5건, 정책 오류·취소 시 다음 묶음 중단, 묶음 ID 및 기존 이력 호환을 확인했다.
- PC·모바일 모의 API: 12장 자동 분할과 묶음 사이 설정 3→2 변경, 비동기 결과 대기, 실패 재요청의 기존 이력 유지, 취소·진행률·기존 검수 기능을 검증했다.
- 실제 AI API 호출·VM/운영 배포·커밋·푸시는 수행하지 않는다.

- 최종 결과: 프런트 단위 **51건 통과**, PC·모바일 브라우저 **50건 통과**, 프런트 빌드 및 변경 파일 공백 검사 통과. 12장 요청의 전송 메타데이터가 정확히 5/5/2로 나뉘고, 각 HTTP 요청에는 이미지가 하나씩 들어감을 확인했다. 모바일 캡처도 확인했다.
