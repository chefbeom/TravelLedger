# 이미지 분석 이력: 날짜 안의 요청 묶음 표시 (2026-10-22)

## 범위

- `날짜 → 한 번에 요청한 묶음 → 기존 개별 분석 행`의 표시 계층을 추가했다. 같은 날짜의 5장·4장·1장 요청을 각각 구분한다.
- 묶음에 요청 시각·원래 요청 건수·현재 페이지에 표시된 상태별 건수를 표시한다. 파일별 내용 보기·삭제·취소·검수·승인 동작은 그대로다.
- 묶음이 이력 페이지 경계에 걸려도 원래 4장 요청을 3장 요청으로 바꾸지 않는다. `4건 요청 묶음`, `이 페이지에 3/4건 표시`, `현재 페이지 · 완료 3건`처럼 구분한다. 기존 8건 단위 이력 조회/페이지 이동은 유지한다.

## 정확한 표시를 위한 식별 정보

- 이전 이력에는 공통 묶음 ID가 없었다. 생성 시각이 가깝거나 파일명이 같다는 이유만으로 과거 요청을 임의로 합치지 않으며, 해당 내역은 `개별 요청 1건`과 묶음 정보 없음 안내로 표시한다.
- 새 요청은 기존 `clientRequestId` 필드에 공통 묶음 토큰·요청 시작 시각·파일 순서·선택 수를 넣는다. 파일마다 요청 ID는 여전히 고유하며 기존 120자 제한 안이다. 서버는 종전과 똑같이 이 식별자를 보관하므로 새로고침 후에도 표시를 복원할 수 있다.
- 화면에서 쓰던 개별 항목 ID는 바꾸지 않는다. 입력칸 적용 대상, 취소 대상, 승인 인덱스에 영향을 주지 않는다.
- 하루를 넘겨 순차 처리되어도 새 묶음은 처음 요청을 누른 날짜 안에 표시한다. 묶음 안에서는 선택한 파일 순서를 사용한다.
- 저장된 이미지만 사용한 서버 재요청은 기존 식별자를 그대로 사용하며 개별 요청으로 표시한다.
- 이 변경으로 백엔드·DB 스키마·API 형식·한 장씩 순차 분석하는 방식·대기 배지의 집계 기준은 바꾸지 않았다. AI에 여러 이미지를 한 번에 보내는 기능이나 일괄 승인/삭제를 추가한 것이 아니다.

## 검증

- 프런트 빌드 및 단위 테스트 36건 통과.
- 신규 단위 검증: 같은 날짜의 5/4/1 묶음, 6개 식별자의 고유성/120자 제한, JSON 재로딩 후 순서, 페이지 경계·날짜 전환, 과거 내역을 임의로 합치지 않음을 확인했다.
- 모의 API PC·모바일 검사 12건 통과. 라이트·다크에서 묶음별 표시와 페이지 전환을 확인하고, 기존 6장 요청이 여전히 6개의 단일 이미지 POST로 순차 처리되며 공통 묶음과 개별 순서를 유지하는지 확인했다. 기존 완료 배지·83건 분할 검수·입력칸 적용 및 모달 동작 검사도 포함했다.
- 운영·VM·실제 AI는 사용하지 않았다. 커밋·푸시는 별도 요청 시 진행한다.
