# 이미지 분석 재요청: 기존 이력 갱신 (2026-10-22)

## 변경한 동작

- 이미지 3건 중 2건이 실패한 뒤 상세 화면에서 각각 재요청해도 새 이력 2건을 만들지 않는다. 원래 3건 묶음의 실패 항목이 `처리 중 → 완료/실패`로 갱신된다.
- 기존 분석 ID, 이미지별 `clientRequestId`, 최초 요청 시각, 묶음·순서, 원본 이미지 참조를 유지한다. 재요청에 선택한 분석 유형과 요청사항은 새 분석에 적용한다.
- `실패 건만 재시도`와 상세 `재요청 검수`가 같은 기존 이력 재실행 경로를 사용한다. 성공한 다른 이미지의 사용자 편집은 건드리지 않는다.
- HTTP 실패로 분석 ID를 받지 못했어도 원래 `clientRequestId`로 본인 이력을 찾는다. 첫 이력 페이지 밖의 항목도 조회할 수 있다. 정말 접수 이력이 없는 404일 때만 최초 접수를 진행하며, 조회 장애를 새 접수로 우회하지 않는다.
- 저장된 원본 이미지를 우선 사용한다. 원본 보관 전 실패했지만 브라우저에 파일이 남아 있으면 같은 이력의 재요청에 파일을 보충할 수 있다. 입력 검증은 유지한다.
- 새 파일을 별도로 선택해 처음 분석하는 동작은 새 요청이다. 과거 버전에서 이미 생긴 중복 이력은 자동으로 삭제하거나 추측해 병합하지 않는다.

## 서버 안전장치

- 본인 이력 + 기존 버전 + 처리 중이 아닌 상태를 조건으로 짧은 독립 트랜잭션에서 원래 행을 재시작한다. 처리 중 다시 누르면 기존 작업을 반환하고 중복 실행하지 않는다.
- 기존 소유권 lease를 확보하고 작업에 인계한다. 동시 분석 제한·접수 한도·취소·큐 거절 시 정리는 유지한다.
- 이미지 완료/실패에도 추론 시작 전 버전 검사를 적용했다. 이전 시도의 늦은 응답이나 오류가 취소 후 새로 시작한 시도의 상태를 덮어쓸 수 없다.
- 재요청 시 이전 결과·오류·완료/취소 시각은 초기화하되 최초 생성 시각은 유지한다. 이미 작성된 가계부 거래 자체를 수정하거나 삭제하지 않는다.
- 새 DB 컬럼이나 마이그레이션은 필요하지 않다. 기존 재요청 API의 응답 형식도 유지한다.

## 검증

- 격리 H2/JPA 검증: 기존 3건 묶음 중 2건 재요청 후 행 수·ID·최초 시각·원본 참조 유지, 처리 중 재클릭의 중복 큐 방지, 소유권 반환, 재실패 후 재시도, 본인 소유 확인 및 이전 버전의 완료/실패 차단.
- 기존 OCR·AI 작업 저장/취소/복구·최종 상태 전이·계층 구조 회귀 검증도 수행했다.
- PC·모바일 모의 API 브라우저 검증: 상세에서 실패한 2건 재요청 후 같은 3건 묶음 유지, 다시 실패한 이력 재시도, 첫 페이지 밖의 실패 이력 재사용, 성공한 결과의 편집 보존 및 기존 병렬 처리·취소·표시 기능.
- 실제 외부 AI 호출이나 VM/운영 배포는 수행하지 않는다. 커밋·푸시는 별도 요청 시 진행한다.

- 최종 백엔드 대상 **160건 통과**, 프런트 단위 **47건 통과**, PC·모바일 모의 API 브라우저 전체 **48건 통과**. 마지막으로 상세 화면에 머무르게 하는 조정 후 핵심 PC·모바일 **8건을 재실행하여 통과**했다. 프런트 빌드와 변경 파일 공백 검사도 통과했다.
- 모바일 캡처에서 `1묶음 · 3건 표시`와 원래 묶음의 `완료 3건`을 확인했다.
