# 이미지 분석·검수 시작 화면 및 대기 배지 (2026-10-22)

## 표시 기준

- ‘분석 내용 확인 및 불러오기’ 탭에 빨간 숫자 배지를 표시한다. 거래 개수가 아니라 **완료된 요청 중 미사용 거래 후보가 남아 있는 요청 개수**다.
- 일부 후보만 사용했다면 그 요청은 1건으로 계속 표시한다. 모든 후보를 승인하거나 입력칸에 적용했으면 제외한다. 실패·취소·처리 중·후보가 없는 요청은 제외한다.
- 목록을 열어 보기만 해서는 대기 표시를 없애지 않는다. 승인 결과는 서버 상태를 사용하고, 입력칸 적용 여부는 기존 브라우저의 적용 마커(localStorage)를 사용한다. 입력칸 적용만 한 상태는 기기 간 공유되지 않는 기존 규칙을 유지한다.

## 화면

- 파일을 선택하지 않았고 탭도 선택하지 않은 첫 진입에도 작업 공간을 확보한다. PC는 가용 화면 안에서 최대 900px 높이, 모바일/짧은 화면은 화면 높이에서 16px 여백을 제외한 크기다.
- 시작 안내, 대기 결과 안내/바로 가기, 이미지 선택·검수·프롬프트 설정의 3개 진입 카드를 제공한다.
- 모달을 `.app-shell` 최상위로 Teleport해 상단 메뉴·테마 버튼이 닫기 버튼을 가리지 않게 한다. 기존 모바일 스크롤 잠금과 Escape 닫기는 유지한다.

## 조회 및 성능

- 인증된 본인의 `/api/ledger/image-analysis/history/review-summary` 읽기 전용 API를 추가했다. 기존 `/api/ledger/ocr` 별칭도 동일하게 적용된다.
- 현재 이력 1페이지(8건)만 세지 않는다. 서버에서 완료된 요청을 ID 키셋 기반 64건 단위로 조회해 요청 ID·후보 수·승인 인덱스만 반환한다. 원문 OCR·거래 내용·이미지 URL·프롬프트는 응답에 포함하지 않는다.
- 모달을 열거나 첫 페이지를 명시적으로 새로고침할 때 갱신한다. 동시 요약 조회는 하나로 합치며, 기존 이력의 조용한 자동 갱신마다 전체 요약을 다시 읽지는 않는다. 현재 세션에서 새로 완료/사용한 결과도 배지에 반영한다.
- 새 테이블/컬럼을 추가하지 않았으므로 이 기능을 위한 DB 마이그레이션은 없다.

## 검증

- 프런트 빌드, 단위 테스트 32건 통과.
- 모의 API PC·모바일 검사 10건 통과: 라이트/다크, 초기 모달 크기와 닫기 버튼 클릭, 빈 상태 진입, 첫 8건이 모두 사용된 경우에도 다음 페이지의 대기 요청 표시, 일부 사용/전체 사용에 따른 건수 변화, 이전 6장 분석 및 대량 검수 기능 회귀 포함.
- 기존 빠른 입력·집계·거래 시트·회전/배치 선택 브라우저 회귀 검사 21건 통과.
- 백엔드/H2 검사 71건 통과: `LedgerImageReviewSummaryTest` 2건, `LedgerImageJobRepositoryTest` 3건, `LedgerOcrControllerTest` 6건, 기존 `LedgerOcrServiceTest` 25건, `BackendArchitectureTest` 35건. 본인 소유권, 처리 상태 제한, 64건 이후 요청 포함, 승인 인덱스 중복/오류, 요약 응답의 거래 내용 제외를 확인했다.
- 운영 서버·실제 AI·VM 배포는 사용하지 않았다. 커밋·푸시는 별도 요청 시 진행한다.
