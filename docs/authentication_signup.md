# 회원가입 및 카카오 로그인 운영 계약

## 가입 흐름

- 초대 링크 가입(`/api/invites/accept`)은 기존처럼 이메일 인증 없이 계정을 만들고 로그인할 수 있습니다.
- 관리자가 공개 회원가입을 켠 경우 `/api/auth/register`는 `202 Accepted`와 함께 인증 메일을 발송합니다.
- 일반 가입 계정은 이메일 인증 전까지 `active=false`로 유지되며 로그인할 수 없습니다.
- 인증 링크는 프런트엔드의 `#/verify-email/{token}`으로 열립니다. 링크를 여는 것만으로 인증하지 않고 가입 시 설정한 2차 비밀번호를 다시 입력한 뒤 `이메일 인증하기`를 누르면 `/api/auth/email-verification/verify`를 호출합니다. 잘못된 PIN은 기존 2차 비밀번호 시도 제한을 적용하며, 이메일 인증 토큰은 사용되지 않습니다. 신규 가입 인증은 별도로 계정별 실패 횟수를 DB에도 기록해 5회 실패 시 15분간 제한합니다. 링크를 재발송하거나 앱 프로세스·노드가 바뀌어도 이 제한을 유지하며 인증 성공 또는 만료 신청 정리 시 기록을 지웁니다. 구버전 노드가 남아 있는 혼합 배포에서는 전체 서버의 제한을 보장할 수 없으므로 모든 노드를 함께 교체해야 합니다. 프로필 이메일 인증은 이미 로그인 상태에서 PIN을 확인하고 요청하므로 링크에서 버튼 확인만 합니다.
- 인증 메일 재전송은 `/api/auth/email-verification/resend`이며 동일 계정에 대해 60초 쿨다운이 적용됩니다. 쿨다운 중에는 기존 링크를 유지하고 메일을 다시 보내지 않으며, 등록되지 않은 이메일 요청과 같은 일반 응답을 반환합니다. SMTP 발송 실패도 같은 일반 응답으로 처리하고 기존 유효 링크를 유지합니다. 전송 성공 직후 DB 확정이 실패하거나 메일 서버 응답이 유실되면 새 링크가 유효하지 않을 수 있으므로 기존 링크 또는 이후 재발송이 필요할 수 있습니다. 가입 화면의 별도 재발송 양식은 새로고침 후나 신규 공개 가입이 닫힌 경우에도 사용할 수 있습니다. 관리자에 의해 중단된 신청이나 7일이 지난 신청은 다시 활성화하지 않습니다.
- 재전송 응답의 본문·상태를 같게 하더라도 실제 발송 대상은 SMTP 처리를 기다리므로 응답 시간으로 존재 여부가 추정될 가능성은 남습니다. 이 조치만으로 가입·재발송 남용을 완전히 차단하지 않으며, 공개 전 실제 환경의 속도 제한과 메일 발송량을 검증해야 합니다.
- 신규 미인증 가입은 마지막 인증 메일 발송 요청부터 7일 동안 유지됩니다. 정상적으로 재발송하면 기한이 갱신되고, 7일이 지난 뒤에는 인증할 수 없습니다. 신규 신청의 발급·확인·정리 기한은 여러 서버가 공유하는 DB 시각을 기준으로 합니다. 정리 작업은 기동 5분 후부터 매시간 최대 1,000건씩 확인하며, 만료 신청의 아이디·이메일·비밀번호/PIN 해시·토큰과 식별 가능한 감사 정보를 제거합니다. DB 참조를 보존하기 위해 재활성화할 수 없는 익명 계정 행만 남깁니다. 정리 실패나 대기량에 따라 실제 식별자 해제는 7일보다 늦어질 수 있으며, 7일 이후 재발송 요청이 도착해도 해당 신청을 다시 연장하지 않고 정리를 시도합니다.
- 자동 정리는 새 코드가 시작한 신청에만 명시적으로 표시합니다. 마이그레이션 전 미인증 신청은 과거 관리자 중단 여부를 안전하게 구별할 수 없으므로 자동 삭제하지 않습니다. 기존 회원, 관리자가 중단한 신청, 관리자 및 연결된 소셜 계정은 자동 정리 대상이 아닙니다. 이 과거 신청의 정리 방침은 별도 확인이 필요합니다.
- 가입 인증 API는 이제 토큰과 `secondaryPin`을 함께 요구하므로 프런트엔드와 백엔드를 함께 배포해야 합니다. 예전 화면이 토큰만 제출하면 인증되지 않으며 새로고침 후 가입 PIN을 입력해야 합니다. 기존 유효 링크는 만료·취소되지 않았다면 새 화면에서 사용할 수 있습니다.
- 관리자가 계정을 비활성화하면 가입 및 프로필 이메일 변경의 미사용 인증 링크가 무효화됩니다. 취소된 가입 대기 계정은 관리자가 다시 활성화한 뒤 인증 메일을 재요청할 수 있습니다. 이미 인증된 비활성 계정은 가입 인증 재전송으로 재활성화되지 않습니다.
- 초대·기존 계정은 로그인 후 프로필에서 이메일과 2차 비밀번호를 입력하여 인증할 수 있습니다. 인증 링크를 열기 전까지 기존 이메일은 유지되며 인증 완료 시에만 변경합니다. 기존 주소와 중복되는 주소는 사용할 수 없습니다.

인증 토큰 원문은 DB에 저장하지 않고 SHA-256 해시만 `email_verification_tokens`에 저장합니다. 메일 발송 실패 시 가입 트랜잭션도 성공으로 남지 않습니다.

**공개 가입 전 검증 필요:** 일반 가입은 이메일 인증 전에 아이디·비밀번호·PIN을 정합니다. 인증 링크에서 가입 PIN을 다시 확인해 다른 사람이 신청한 계정을 메일 수신자가 모르고 활성화할 가능성과 자동 링크 검사에 의한 인증을 줄였지만, 사회공학이나 추측하기 쉬운 PIN까지 완전히 막는다고 단정할 수 없습니다. 과거 미인증 신청은 자동 정리하지 않으며, 남은 사전 계정 탈취 위험과 실제 SMTP·운영 DB 및 동시성 검증을 마치기 전 공개 이메일 가입을 운영에서 켜지 않습니다.

## 카카오 로그인 흐름

- `GET /api/auth/oauth/kakao/start`가 일회성 OAuth state를 세션에 저장한 뒤 카카오로 이동합니다.
- 콜백은 state와 5분 유효시간을 검증하고 카카오의 인증된 이메일을 확인합니다.
- 이미 연결된 소셜 계정은 바로 로그인합니다.
- 새 계정은 공개 가입 정책이 켜져 있을 때만 `#/oauth/kakao/complete`로 이동해 표시 이름과 숫자 8자리 2차 비밀번호만 입력합니다. 공유 기능 호환을 위한 내부 ID가 생성되지만, 일반 로그인 비밀번호는 만들지 않습니다.
- 가입 화면은 `GET /api/auth/oauth/kakao/registration`으로 세션의 인증된 이메일·닉네임·만료 시각을 조회합니다. 닉네임은 표시 이름의 초기값으로 사용하고 사용자가 수정할 수 있습니다. 이메일·소셜 식별자는 가입 폼에서 받지 않습니다.
- 가입 대기는 인증 후 10분 동안 유효합니다. 만료·취소된 세션으로는 가입할 수 없고, 완료 후에는 같은 대기 세션을 재사용할 수 없습니다. 입력 오류는 수정 후 다시 제출할 수 있습니다.
- `POST /api/auth/oauth/kakao/cancel`은 카카오 가입 대기와 OAuth·계정 연결 상태를 지웁니다. 새로운 카카오 인증을 시작할 때도 이전 대기를 제거합니다. 가입 완료·취소 POST는 기존 CSRF 보호를 유지합니다.
- 인증 취소, state 불일치/만료, 이메일 인증·동의 부족, 기존 이메일 계정, 공개 가입 마감, 제공자 통신 실패를 고정 오류 코드로 구분합니다. 카카오 응답 원문이나 토큰을 URL·화면에 노출하지 않습니다.
- 신규 가입을 닫아도 이미 연결된 활성 계정의 카카오 로그인은 유지합니다. 비활성 계정은 로그인할 수 없습니다.
- 기존 이메일 계정과 카카오 계정을 자동 병합하지 않습니다. 로그인한 기존 계정에서 2차 비밀번호와 별도의 카카오 인증을 거쳐 명시적으로 연결하며, 연결 후에도 기존 ID·비밀번호 로그인은 유지합니다. 다른 계정에 이미 연결된 카카오 계정은 가져올 수 없습니다. 인증을 시작한 뒤 PIN·비밀번호·이메일이나 권한 등 보안 상태가 바뀌면 해당 연결 시도는 무효가 되어 다시 시작해야 합니다. 연결 확인값은 서버 세션에 암호화해 보관하고 콜백에서 일회성으로 제거합니다.

카카오 간편가입에는 서비스 일반 로그인 비밀번호가 필요하지 않습니다. 사용자가 선택한 정책에 따라 카카오 재로그인은 추가 PIN 없이 처리하고, 계정 연결·이메일 변경·개인정보 보호 등 민감 작업에는 2차 비밀번호를 사용합니다. 카카오에서 인증된 이메일에는 별도 인증 메일을 발송하지 않습니다.

카카오 개발자 콘솔의 Redirect URI는 다음 백엔드 주소로 등록합니다.

```text
https://<공개 앱 주소>/api/auth/oauth/kakao/callback
```

## 운영 설정

실제 비밀번호·클라이언트 시크릿은 저장소에 넣지 않고 운영 secret/env 관리 수단으로 주입합니다.

- 이메일: `APP_AUTH_EMAIL_VERIFICATION_ENABLED`, `APP_AUTH_EMAIL_VERIFICATION_BASE_URL`, `APP_AUTH_EMAIL_VERIFICATION_TOKEN_VALIDITY`, `APP_AUTH_EMAIL_VERIFICATION_FROM`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM`
- 인증 링크의 기본 주소는 HTTPS여야 합니다. 로컬 개발을 위한 `localhost`, `127.0.0.1`, `[::1]`에 한해 HTTP를 허용하며, 사설망을 포함한 다른 주소의 HTTP는 거부합니다. 테스트 VM에서도 인증 링크를 사용하려면 접근 가능한 HTTPS 주소를 설정해야 합니다.
- 미인증 가입 정리 스케줄러: `APP_AUTH_EMAIL_PENDING_CLEANUP_ENABLED` (기본 `true`). `false`는 정기 작업만 중단하며, 7일 이후 재발송 요청 시 만료 정리 시도는 유지됩니다. 오류 로그에는 계정 식별자나 예외 원문을 남기지 않습니다.
- 카카오: `APP_AUTH_KAKAO_ENABLED`, `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`, `KAKAO_REDIRECT_URI`, `KAKAO_FRONTEND_BASE_URL`
- 카카오 Redirect URI·프런트엔드 및 카카오 API 주소 역시 HTTPS를 사용해야 합니다. 로컬 개발용 `localhost`, `127.0.0.1`, `[::1]`만 HTTP를 허용합니다. 원격 HTTP가 설정되면 카카오 로그인 또는 해당 연결 해제 기능이 설정되지 않은 것으로 처리됩니다.
- 카카오 계정 연결의 서버 세션 보호에는 기존 `SESSION_SEAL_KEY`(미설정 시 `JWT_KEY`)를 사용합니다. 여러 서버를 운영한다면 모든 노드에 같은 안전한 키와 공유 세션 저장소를 설정해야 합니다. 키를 바꾸거나 세션이 만료된 경우 진행 중인 연결은 다시 시작해야 합니다.
- 향후 탈퇴 시 연결 해제에 필요한 서버 전용 `KAKAO_ADMIN_KEY`는 REST API 키나 Client Secret과 별도이며 브라우저·로그·저장소에 공개하지 않습니다. 연결 해제 클라이언트는 준비되었지만 회원 탈퇴 전체 처리는 아직 완성되지 않았습니다.
- 선택 설정 `KAKAO_EXPECTED_APP_ID`는 카카오 콘솔의 **앱 ID**(REST API 키가 아닌 숫자)를 지정합니다. 설정 시 로그인마다 카카오 토큰 정보의 앱 ID·회원번호·유효기간을 확인하며, 불일치·장애 시 해당 로그인은 실패합니다. 설정하지 않으면 기존 로그인 방식은 유지되지만 앱 출처를 새로 검증하지 않습니다. `V20261103_050`을 먼저 적용하고 기존 회원이 동일한 카카오 앱으로 가입했는지 확인한 후 설정합니다. 기존 행에는 값을 일괄 추정하지 않고 해당 회원의 검증된 다음 로그인 시 기록합니다. 이미 기록된 회원은 설정 해제나 다른 앱으로의 변경으로 검증이 약해지지 않도록 카카오 로그인을 거부합니다. 운영 전 실제 제공자·마이그레이션 검증이 필요합니다.
- `KAKAO_ADMIN_APP_ID`는 어드민 키의 앱을 운영자가 별도로 확인했다는 선언일 뿐, 키의 실제 출처를 프로그램이 증명하지는 않습니다. 자동 연결 해제는 이 값과 검증된 회원 앱 ID 및 `KAKAO_EXPECTED_APP_ID`가 모두 같아야 하며, 키 자체가 같은 앱의 것인지 카카오 콘솔에서 직접 검증해야 합니다. 미확인 회원·설정 불일치는 수동 검토하고, 회원 탈퇴와 외부 삭제 작업은 아직 공개되지 않았습니다.
- 필요하면 `KAKAO_AUTHORIZATION_URI`, `KAKAO_TOKEN_URI`, `KAKAO_USER_INFO_URI`, `KAKAO_TOKEN_INFO_URI`, `KAKAO_UNLINK_URI`와 timeout 값을 조정합니다.

배포 전에는 SMTP 인증 메일이 실제로 발송되는지, 카카오 콘솔 Redirect URI와 `KAKAO_REDIRECT_URI`가 정확히 일치하는지, 앱과 메일 링크가 HTTPS를 사용하는지 확인합니다.

## 키 준비 후 활성화 절차

현재 소스와 배포 예시의 `APP_AUTH_KAKAO_ENABLED` 기본값은 `false`로 유지합니다. 이 구현 작업에서 운영 공개 가입이나 카카오 실연동을 켜지 않습니다.

1. 카카오 개발자 앱의 로그인 사용 설정과 REST API 키를 준비하고, 이메일(`account_email`)·닉네임(`profile_nickname`) 제공 동의항목을 확인합니다. 이메일을 받았더라도 `is_email_valid`와 `is_email_verified`가 참인 경우에만 신규 가입에 사용합니다. [카카오 REST API 문서](https://developers.kakao.com/docs/ko/kakaologin/rest-api)
2. 등록한 Redirect URI를 `KAKAO_REDIRECT_URI`에 정확히 동일하게 지정합니다. `KAKAO_FRONTEND_BASE_URL`은 해시 경로 없는 공개 프런트엔드 주소입니다. REST API 키는 `KAKAO_CLIENT_ID`에, Client Secret은 카카오 앱의 활성화 설정에 맞춰 `KAKAO_CLIENT_SECRET`에 서버 환경변수로 주입합니다. 키를 저장소·채팅·프런트엔드 코드에 넣지 않습니다.
3. 프런트엔드와 백엔드를 함께 배포하기 전에 기존 `V20260831_021__account_email_verification_social_login.sql`과 신규 `V20261031_034__social_only_password.sql`부터 `V20261103_049__travel_plan_storage_origin.sql`까지의 마이그레이션을 확인하고 환경에 맞는 적용 절차를 검증합니다. `034`는 기존 비밀번호 값은 유지하면서 nullable을 허용합니다. 간편가입은 nullable 변경이 없으면 안전하게 거절합니다. `040`은 기존 자동 로그인 토큰의 소유자를 이관하며, 소유자를 확인하지 못한 토큰은 다시 로그인해야 합니다. `041`·`042` 이후에는 사용자가 선택한 기존 접근·로그인 실패 기록 익명화 작업이 기본 설정에서 자동 시작되므로 범위와 백업을 사전에 확인해야 합니다. `043`~`047`은 파일·업로드의 저장 위치 이력이나 정리 정보를 추가하고, `048`은 초대 익명화·철회 정보를, `049`는 공유 여행 이전을 준비하기 위한 저장 경로 이력을 추가합니다. 기본 설정은 Flyway가 꺼져 있고 Hibernate `ddl-auto`는 `update`이므로 기동 중 신규 테이블 등이 자동 생성될 수 있지만, 이것이 명시적 마이그레이션의 적용이나 검증을 보장하지는 않습니다. 배포 중이던 구형 가입 대기 세션은 다시 카카오 인증을 받아야 합니다.
4. 키 설정 후 `APP_AUTH_KAKAO_ENABLED=true`로 전환하고 `GET /api/auth/registration-options`의 `socialLoginProviders`에 `KAKAO`가 표시되는지 확인합니다. 이는 설정 감지일 뿐 실제 카카오 인증 성공을 보증하지 않습니다. 관리자 가입 정책 화면에서도 설정 감지/누락 상태를 표시하며 키 값은 표시하지 않습니다.
5. 관리자의 공개 회원가입 ON/OFF는 기존 정책을 사용합니다. 공개 전 실제 카카오 신규 가입·재로그인·인증 취소·중복 이메일·만료·PC/모바일 세션 유지까지 별도 검증합니다. 공개 가입을 켜면 기존 이메일 가입 경로도 함께 열리므로 이메일 가입을 제공할 경우 SMTP 실발송 검증도 필요합니다.

OAuth state는 서버 세션에 보관하고 일회성·5분 만료를 검증합니다. 이는 카카오가 안내하는 [state 기반 CSRF 방어 권장 사항](https://developers.kakao.com/docs/ko/getting-started/security-guideline)을 따릅니다. 가입 조회와 인증 리다이렉트 응답에는 `Cache-Control: no-store`를 지정합니다.

- `PublicRegistrationIntegrationTest`, `ProfileCredentialIntegrationTest`: 기존 이메일/초대 가입, 일반 로그인, 비밀번호/2차 비밀번호 기능을 회귀 검증합니다.

## 회원 탈퇴 구현 상태

공유 가족 앨범의 소유권을 활성 멤버에게 이전하고 다른 멤버의 사진을 보존하는 서비스와 카카오 연결 해제 클라이언트는 개별 테스트 대상입니다. 사전 확인 화면과 조회 API는 있지만, **실제 회원 탈퇴 요청이나 완료 처리는 아직 제공하지 않습니다.** 가계부·지도·드라이브·공유자료, 오브젝트 스토리지와 파생 썸네일, 캐시·백업, 기존 세션, 외부 AI/검색 저장소의 삭제 범위 및 실패 재시도 절차를 연결하고 검증해야 합니다. 소유권 이전 대상이 없거나 카카오 연결 해제에 실패하면 탈퇴 완료로 표시하지 않아야 합니다. 사용자가 백업 최대 보존기간으로 30일을 선택했지만, 자동 폐기와 복원 시 탈퇴 반영은 아직 구현·검증되지 않았습니다. 법적 보존 예외도 확인해야 합니다.
