# 달력 팔레트 설정의 기기 간 유지

## 적용 기준

같은 계정으로 접속하면 서버 DB에 저장한 팔레트 배치·너비·높이, 카드 구성·크기·글자·색상·상세 표시, 달력·입력 표시 기본값을 복원한다. 화면 폭에 따른 반응형 표현은 유지하므로 컴퓨터마다 실제 픽셀 너비까지 같다는 의미는 아니다.

편집 후 **변경사항 저장**을 눌러 서버 저장이 성공해야 다른 기기에 반영된다. 저장 전 초안은 동기화하지 않는다. 다른 기기에서 저장한 내용은 다시 접속/새로고침하여 불러온다. 열려 있는 다른 기기로 실시간 전파하는 기능은 포함하지 않는다.

## 확인한 원인

- 저장은 이미 인증 계정별 `UserLayoutSetting` 두 scope(`household-calendar`, `household-calendar-view`)와 사용자 집계 설정 JSON을 사용하는 구조였다.
- 배치 초기 로딩에서 브라우저 `savedAt`이 서버 `updatedAt`보다 크면 로컬 배치를 우선했다. PC 시계가 앞서거나 다른 PC에서 저장한 이후에도 오래된 캐시가 우선될 수 있었다.
- 공통 편집기를 열 때에도 서버 배치가 존재하는데 로컬 값을 초안으로 유지하여, 다시 저장하면 다른 기기의 최신 배치를 되돌릴 수 있었다.
- 기기 간 크기 복원 검사 중 모바일 편집창의 숫자 입력도 재현했다. 스크롤로 편집창이 다시 그려지면 `:value`와 `@change` 사이의 미확정 입력이 이전 값으로 초기화될 수 있었다.

## 수정

- 서버 배치가 존재하면 클라이언트 시각을 비교하지 않고 서버 값을 적용한다. 로컬 캐시는 로딩/조회 실패 시 보조 값으로만 사용한다.
- 편집 세션도 서버 설정을 기준으로 시작한다. 서버에 값이 없는 옛 브라우저 전용 설정만 유지하고, 저장 버튼을 활성화하여 명시적으로 계정에 옮길 수 있게 안내한다.
- 화면을 떠난 뒤 도착하는 이전 배치/보기 요청은 무효화한다. 기존 저장 revision 충돌 처리, 계정별 접근권한, 원자적 저장과 취소 복원은 유지한다.
- 직접 편집창의 크기 입력은 로컬 입력 초안을 유지하면서 실제 카드/팔레트에 반영한다. 부분 입력 중에는 정규화 값으로 덮지 않으며, 포커스를 떠날 때 허용 범위로 정리한다. 저장 직전 blur 여부와 관계없이 입력 내용이 저장 초안에 반영된다.
- 새 DB 테이블·칼럼·마이그레이션은 추가하지 않는다.

## 검증

- 저장소·쿠키를 공유하지 않는 두 Playwright 브라우저 컨텍스트가 모의 계정 저장소만 공유하도록 구성했다.
- 첫 기기에서 배치·카드 크기·이름·글자·색·상세 표시·입력 표시를 변경하여 저장한 뒤, 비어 있는 두 번째 기기에서 복원한다.
- 두 번째 기기에서 다시 저장한 뒤, 2099년의 캐시 시각을 가진 첫 기기가 새로고침해도 서버 최신 배치를 사용하고 읽기만으로 저장 요청을 만들지 않는지 검사한다.
- 서버 값이 없는 옛 배치의 명시적 계정 이관과 서버 조회 실패 시 캐시가 계정 값을 덮어쓰지 못하는 동작을 검사한다.
- H2 통합 테스트는 서로 다른 인증 세션에서 같은 계정의 전체 설정이 동일하게 복원되고, 다른 계정에는 적용되지 않는지 확인한다.
- 브라우저 검증은 로컬 모의 API, 백엔드 검증은 격리 H2 DB를 사용한다. 실제 VM/운영 배포 검증은 아니다.

### 실행 결과

- 수정 전: 시계가 앞선 브라우저 캐시 우선 문제 및 모바일 너비 입력 누락을 재현했다.
- 수정 후: 기기 간 복원·개인화·WYSIWYG·입력·공유 브라우저 테스트 95개 통과, 데스크톱 GridStack 전용 항목의 모바일 중복 실행 3개 제외.
- 백엔드 설정 통합 테스트 12개와 집계 설정 서비스 테스트 4개 통과. 프런트 단위 테스트 59개 및 프로덕션 빌드 통과.
- PWA/모바일 기준, DB 마이그레이션 규칙, 변경 작업 파일 BOM 검사와 `git diff --check` 통과.
- VM/운영 배포는 이 검증에 포함하지 않았다.
