# 날짜·조회 팔레트 이동 및 집계 2차원 격자 보완 (2026-10-25)

## 원인

- 날짜·조회 줄은 저장 배치에 없는 잠긴 표시 행이었다. 다른 팔레트를 이동해도 이 줄을 직접 옮길 수 없어 빈 행을 사용자가 정리할 수 없었다.
- 집계 카드는 `flex-wrap`으로 줄바꿈하여 같은 줄에서 가장 높은 카드가 다음 줄의 시작점을 결정했다. 2×2 카드 옆의 작은 카드 아래에 빈 셀이 있어도 후속 카드가 들어가지 못했다. 일부 구형 스타일의 8열 배치 규칙도 새 격자와 충돌했다.

## 수정

- 날짜·조회 줄을 `calendar-query` 팔레트로 저장한다. 손잡이/배경으로 마우스·터치 이동, 손잡이 방향키 이동 및 높이 조절을 지원한다. 날짜·필터·거래 시트 버튼은 드래그 시작 대상에서 제외한다.
- 조회 줄은 전체 9열, 높이 1~12행이며 다른 팔레트와 동일한 좌표·간격을 사용한다. 편집 중의 위치를 저장 후와 다른 브라우저에서도 복원한다.
- 기존 네 팔레트 설정은 종전 표시 줄을 포함한 다섯 팔레트 좌표로 한 번만 읽기 변환한다. 이미 다섯 팔레트인 설정은 재투영하지 않으며, 조회/취소만으로 서버 설정을 덮어쓰지 않는다.
- 모바일 줄바꿈에 필요한 표시 높이와 계정에 저장된 높이를 분리한다. 모바일 순서를 바꾸는 것만으로 데스크톱 높이를 확대 저장하지 않는다.
- 집계 내부는 9열·8px 간격의 CSS Grid와 2차원 셀 점유 계산을 사용한다. 저장된 순서대로 들어갈 수 있는 첫 빈 영역에 배치하므로 2×2 카드 옆/아래 빈 셀도 사용한다.
- 카드와 안내 셀은 같은 열/행 좌표를 사용한다. 드래그 중 정수 칸 미리보기가 실제 카드와 주변 배치에 즉시 반영되며, Escape/포인터 취소 시 원복한다. 글자·색·이웃 카드 크기는 유지한다.

## 저장 호환성

- 기존 계정별 `household-calendar` JSON에 선택 팔레트를 추가하며 신규 테이블/DB 마이그레이션은 없다. 전체 개인화 저장은 배치 문서 버전 4를 사용한다.
- 백엔드는 기존 필수 네 ID와 선택 `calendar-query` ID를 검증한다. 조회 줄의 x=0, 너비=9 및 정수·범위·중복 조건을 확인한다.
- 구형 클라이언트가 네 팔레트로 다시 저장해도 이미 저장된 조회 팔레트는 보존한다. 계정 잠금, revision 충돌, 원자적 저장 계약을 유지한다.
- 집계 개별 좌표를 별도 저장하지 않는다. 기존 카드 순서와 `cardColumns/cardRows`로 같은 2차원 배치를 계산한다. 구형 픽셀 값은 보존하고 화면에서 정수 칸으로 스냅한다.
- 프런트엔드와 백엔드를 함께 배포해야 새 조회 팔레트 저장을 사용할 수 있다. 거래 입력·공유·집계 계산·AI 기능은 변경하지 않는다.

## 검증 범위

- `calendar-query-movable-and-grid.spec.js`: 빈 상단 행으로 이동, 실제 마우스/터치 이동, 조회 버튼 조작, 저장/새로고침/다른 컴퓨터 복원, 2×2 카드와 안내 셀의 실제 경계 및 빈 셀 채우기.
- 기존 팔레트 정렬·실시간 크기 미리보기·개인화 저장/취소/충돌·기기 간 복원·모바일/테마·달력 조회·빠른 입력·거래 공유 브라우저 검증을 병행한다.
- 단위 테스트는 호환 변환의 일회성·원본 불변, 2차원 비중첩 배치와 크기 제한을 확인한다.
- 격리 H2 통합 검증은 다섯 팔레트 저장/복원, 구형 요청 보존, 잘못된 조회 위치/크기의 원자적 거부를 확인한다.
- 로컬 모의 API/격리 H2를 사용한다. VM/운영 배포나 운영 데이터 변경은 포함하지 않는다.

- 프로덕션 빌드 및 프런트 단위 테스트 69건 통과.
- 백엔드 개인화 통합 16건, 집계 설정 서비스 4건으로 총 20건 통과.
- PWA/모바일 기준, DB 마이그레이션 규칙, 변경·신규 작업 파일의 UTF-8 BOM 검사 및 `git diff --check` 통과.
- PC의 2×2 실제 카드/안내 셀 배치와 PC·모바일 조회 줄 캡처를 시각 확인했다. VM/운영 환경의 직접 배포는 수행하지 않았다.
