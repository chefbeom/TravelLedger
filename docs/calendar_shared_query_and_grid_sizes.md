# 공통 달력 조회 줄과 집계 카드 칸 단위 크기 (2026-10-25)

## 화면 배치

- 개인화 설정/대시보드 편집 버튼 위치는 유지한다.
- 날짜·연월·오늘·월/주 보기·표시 기준·거래 시트 열기를 달력과 빠른 입력 양쪽 위의 공통 줄로 분리한다. 모바일에서는 같은 순서를 유지하며 필요한 만큼 줄바꿈한다.
- `calendar-query`는 전체 9열을 사용하는 이동 가능한 다섯 번째 팔레트이다. 기본적으로 달력/입력 위에 표시하지만 손잡이로 빈 행으로 옮길 수 있고, 저장한 좌표를 조회/편집에 함께 적용한다. 이전 네 팔레트 설정은 기존 표시 위치를 유지하도록 한 번만 호환 변환한다. 상세 내용은 `calendar_query_palette_and_dense_grid.md`를 참고한다.
- GridStack 재생성 전 원본 좌표를 복원하고, 편집 종료 후 남은 위치 스타일은 일반 CSS Grid에 적용하지 않는다. 임시 조회 필터, 거래 입력·공유, 계정 기본값 저장 방식은 유지한다.

## 집계 카드 크기

- 선택 카드만 너비/높이를 칸 단위로 조절한다. 모서리 드래그는 정수 칸에 스냅하고 방향키는 한 칸씩 조절한다. 선택 카드 옆 편집창과 전체 설정도 같은 열/행 선택을 사용한다.
- 너비는 집계 내부 9열(간격 8px) 중 1~9열, 그래프는 최소 2열이다. 높이는 대시보드와 같은 행 피치 중 1~12행이며 실제 카드 높이는 `행 수 × 피치 - 8px`이다.
- 모바일은 화면 너비를 사용하며 저장된 데스크톱 열 수를 보존한다. 모바일 드래그/방향키는 높이만 변경한다. 설정창에서는 다른 기기에서 사용할 열 수도 지정할 수 있다.
- 글자 크기·색과 이웃 카드 크기는 독립적으로 유지한다. 작은 칸 안의 긴 내용은 내부 스크롤로 접근한다. Escape/포인터 취소 시 미리보기만 원복하며, 저장 전에는 서버를 변경하지 않는다.

## 저장·호환성

- 기존 개인화 JSON에 선택 필드 `cardColumns`, `cardRows`를 추가한다. DB 스키마 마이그레이션은 없다.
- 새 필드가 없거나 `null`/`0`이면 기존 `cardWidth`, `cardHeight` 및 자동 크기 설정을 표시 크기의 기준으로 사용한다. 2026-10-25 추가 수정에서는 이 표시 크기도 가까운 정수 칸으로 스냅해 혼합 카드의 정렬을 맞춘다. 원본 픽셀 값은 변경하지 않으며 읽기만으로 계정 설정을 덮어쓰지 않는다.
- 새 칸 값을 저장해도 기존 픽셀 값은 남긴다. 칸 설정을 비우면 원래 픽셀 값을 기준으로 스냅한 표시 크기로 돌아간다. 구형 클라이언트가 새 필드를 생략해 저장해도 기존 칸 값이 유지된다.
- 서버에서 정수/허용 범위를 검증하며 기존 revision 충돌·실패 시 초안 유지·취소·기기 간 복원 규칙을 유지한다.

## 검증 범위

- `calendarQueryLayout.test.js`, `calendarWidgetGrid.test.js`: 이전 설정의 일회성 호환 변환, 사용자 배치 경계, 구형 크기 유지, 칸 제한·스냅 및 2차원 셀 배치 계산.
- `calendar-widget-grid.spec.js`: 다른 브라우저 세션 복원, PC/모바일 드래그·방향키·취소, 구형 픽셀 복귀, 1440/1024/390/320px 편집/조회 일치.
- `calendar-shared-controls.spec.js`, `calendar-toolbar-layout.spec.js`, `calendar-layout-alignment.spec.js`: 공통 조회 줄, 기존 컨트롤 실행, 저장 좌표 불변과 배치 정렬.
- 기존 개인화·WYSIWYG·기기 간 동기화·입력·공유 회귀 검증을 병행한다.
- H2 백엔드 검증: 칸 값 저장/복원, 구형 클라이언트 호환, 범위 거부, 다른 계정/브라우저 세션 복원.
- 로컬 모의 API와 격리 H2 DB를 사용한다. VM/운영 배포나 AI 실호출은 수행하지 않는다.
