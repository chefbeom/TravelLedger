# 달력 조회 도구와 대시보드 설정 분리

## 화면 구성

- 대시보드 상단 오른쪽의 **개인화 설정 / 대시보드 편집**은 유지한다. 왼쪽에는 대시보드 구성 영역임을 안내한다.
- 연도·월·이전/다음 월·오늘, 월/주 보기·이전 주 범위·표시 기준·거래 시트 열기는 **달력 팔레트 내부의 날짜 칸 바로 위**로 이동한다. 팔레트를 옮겨도 조회 도구가 함께 이동한다.
- 일반 화면에는 현재 연·월 제목만 표시한다. **달력 영역** 이동 표시는 편집할 때만 같은 제목 자리에 오버레이로 표시한다. 빈 편집용 배너를 일반 화면에 남기지 않으며, 모드 전환으로 달력 내용의 좌표와 높이가 달라지지 않는다.
- 편집 도구 버튼과 월 제목의 공간은 겹치지 않게 분리한다. 날짜/조회 컨트롤은 드래그 시작 대상에서 제외하고, 편집용 제목과 이동 손잡이만 배치 이동에 사용한다.
- 좁은 팔레트에서는 날짜 도구와 조회 도구를 줄바꿈하고, 선택 문구가 잘리지 않게 너비를 확보한다. 거래 시트 열기는 필요하면 별도 전체 너비 행에 둔다. 터치 컨트롤은 최소 44px 높이다.
- 데스크톱에서 조회 도구가 차지하는 공간 때문에 날짜 칸의 수입·지출 정보가 잘리지 않게 최소 행 높이를 유지한다. 공간이 부족하면 기존 팔레트 내부 스크롤로 접근한다. 저장된 팔레트 위치·크기를 강제로 변경하지 않는다.

## 유지하는 동작

기존 연도·월 이동, 오늘, 월/이번 주/이전 주 범위, 표시 기준, 거래 시트 열기의 핸들러와 상태를 그대로 사용한다. 임시 조회 필터는 계정 기본 설정을 자동으로 덮어쓰지 않는다. 기기 간 설정 복원 보완도 유지한다. 새 API나 DB 마이그레이션은 없다.

## 검증

- 1440 / 1024 / 390 / 320px, 기본 / 다크 테마에서 도구가 달력 위에 있고 팔레트 밖으로 넘치지 않는지 확인한다.
- 일반 화면의 편집 배너 부재, 편집 상태에서만 이동 표시·커서 노출, 모드 전환 전후 조회 도구와 날짜 그리드의 좌표·크기 차이 1px 미만을 확인한다.
- 연·월·오늘·월/주 범위·표시 기준·거래 시트 열기를 실제 브라우저로 실행한다. 이전 2주 보기는 기존처럼 기준 주를 포함한 3개 주를 표시한다.
- 개인화 저장/취소, WYSIWYG 이동·크기 조절, 날짜/시간 입력, 기기 간 복원 및 공유도 함께 회귀 검증한다.
- 검증은 로컬 모의 API를 사용한다. VM/운영 배포는 포함하지 않는다.

실행 결과: 관련 브라우저 테스트 99개 통과, 데스크톱 전용 항목의 모바일 중복 3개 제외. 단위 테스트 59개와 프로덕션 빌드, PWA/모바일 기준, DB 마이그레이션 규칙, 변경 작업 파일 BOM 검사 및 `git diff --check`도 통과했다. VM/운영 배포는 이 검증에 포함하지 않았다.
