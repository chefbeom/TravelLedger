# 달력 가계부 대시보드 직접 편집 (WYSIWYG)

## 문제와 변경 기준

- 이전에는 편집 중 GridStack의 고정 칸 배치와 일반 화면의 콘텐츠 높이 기반 배치가 달랐다. 편집용 버튼도 카드 내부 공간을 차지해 저장하면 카드 크기와 줄바꿈이 달라졌다.
- 모달로 여는 거래 시트가 편집 중에는 강제로 팔레트에 포함되어 불필요한 공간과 이동이 발생했다.
- 별도의 전체 설정 창에서 위치·크기·내용을 바꾸므로 실제 대상과 결과를 연결하기 어려웠다.

`calendar_personalization_redesign_20261022.md`의 통합 저장·취소·충돌 처리 원칙은 유지한다. 단, 전체 설정 창을 편집의 필수 진입점으로 쓰던 방식을 실제 화면에서의 직접 조작으로 보완한다.

## 공통 배치 모델

- 데스크톱: 편집/조회 모두 같은 9열, 행 높이, 4px 안쪽 여백을 사용한다. GridStack은 편집 중에만 활성화하지만 저장 후 CSS Grid도 동일한 좌표와 크기를 사용한다.
- 화면 너비가 변경되면 조회 중에도 동일한 행 높이 계산식을 적용한다. 저장 없이 화면 크기를 바꾸거나 편집을 취소해도 저장 좌표를 재배치하지 않는다.
- 모바일: 모든 팔레트 너비는 화면에 맞추고, 저장된 순서와 높이를 편집/조회에 공통 적용한다. 높이 한 칸은 112px이다. 데스크톱 너비 값은 모바일 조작으로 바꾸지 않는다.
- 팔레트 안에서 콘텐츠가 넘치면 내부 스크롤로 접근한다. 저장할 때 콘텐츠 길이 때문에 팔레트 경계가 늘어나지 않는다.
- 거래 시트가 `modal`이면 편집/조회 모두 팔레트에서 제외한다. `inline`으로 명시적으로 선택한 경우에만 함께 배치한다. 숨겨진 팔레트 설정은 보존한다.
- 편집 도구는 오버레이로 표시한다. 달력 헤더와 실제 위젯은 두 모드에서 같은 공간을 사용한다.

## 직접 조작

- 팔레트 윗부분 또는 이동 손잡이를 잡아 이동한다. 커서는 `grab` → `grabbing`으로 변하고 예상 배치 지점을 표시한다.
- 팔레트 오른쪽 아래 모서리를 끌어 크기를 조절한다. 데스크톱은 칸에 맞춰 너비·높이를 변경하고, 모바일은 높이를 변경한다.
- 집계 카드도 개별 이동 손잡이와 크기 조절 모서리를 제공한다. 드래그 중 실제 카드 크기를 먼저 보여주고, 놓을 때 초안에 반영한다.
- 방향키로도 이동·크기 조절이 가능하다. 위젯 크기는 기본 20px, Shift+방향키는 10px 단위다. 포인터 취소/Escape 시 진행 중인 직접 조작을 취소한다.
- 집계 제목은 카드에서 직접 입력한다. 상세 내용 설정은 선택 대상 옆의 작은 비모달 편집창으로 열어 결과를 실제 카드에 즉시 반영한다. 모바일에서는 화면 하단 편집창을 사용한다.
- 카드 설정: 종류·집계 기간·금액 기준·결제수단·월 목표·1회 지출 기준·글자 크기/색·카드 크기·기간/상세 표시·그래프 선/비교선/Y축 최대값·순서·복제·숨기기·삭제.
- 달력/입력 팔레트 설정도 해당 대상에서 연다. 숨긴 팔레트/위젯은 편집 툴바에서 다시 표시할 수 있다. 전체 설정 창은 기본값·초기화·고급 설정을 위해 유지한다.
- 그래프 상세창은 팔레트 밖으로 Teleport하여 내부 스크롤/클리핑의 영향을 받지 않는다.

## 저장 및 호환성

- 초안과 실제 저장은 분리한다. 직접 조작만으로 서버에 자동 저장하지 않는다. 기존 단일 개인화 저장 요청, revision 충돌 확인, 저장 실패 시 초안 유지, 취소 복원을 유지한다.
- 집계 위젯에 선택 필드 `cardWidth`, `cardHeight`, `showPeriod`, `showDetails`를 추가한다.
- 너비는 200~1200px, 높이는 160~800px이며, 그래프 직접 조절의 최소 너비는 280px이다. 실제 화면에서는 팔레트 너비 이내로 제한한다. `0`/빈 크기는 자동 크기로 복원한다.
- 이전 저장 내용은 기간/상세 표시를 켠 상태로 읽는다. 새 필드를 생략한 이전 API 저장 요청도 기존 새 필드 값을 보존한다.
- 기존 사용자 JSON 설정에 저장하므로 DB 스키마 변경/신규 마이그레이션은 없다. 새 크기/상세 설정을 보존하려면 프런트엔드와 백엔드를 함께 배포한다.
- 거래 입력·공유·AI 요청·집계 계산의 업무 로직과 API 계약은 변경하지 않는다. 앞선 빠른 거래 입력의 단일 폼/날짜·시간 수평 배치 수정도 유지한다.

## 검증 범위

- 실제 브라우저 좌표로 편집/저장/새로고침 후 팔레트와 카드의 위치·크기 차이가 1px 미만인지 확인한다. 1440/1024/390px 화면과 기본/다크 테마를 포함한다.
- 마우스 드래그/리사이즈, 모바일 네이티브 터치 이동/리사이즈/내부 스크롤, 키보드 접근을 확인한다.
- 내용·글자·색·상세 표시 변경, 저장 복원, 취소/충돌/실패, 모달 거래 시트 제외 및 인라인 시트 포함을 검증한다.
- 백엔드 H2 통합 테스트로 새 필드 저장/조회, 이전 요청 호환성, 자동 크기 복원, 잘못된 크기의 원자적 거절을 확인한다.
- 브라우저 테스트는 로컬 모의 API를 사용한다. 운영 AI/운영 데이터/VM 배포 검증을 의미하지 않는다.
