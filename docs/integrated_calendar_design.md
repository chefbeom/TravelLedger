# 통합 달력 구현 설계

상태: 통합 달력, 개인 일정, 공유 자료 선택과 원본 화면 연결을 구현했다. 운영 DB 적용과 실제 운영 데이터·기기 검증 및 배포는 수행하지 않았다.

## 확인한 기존 구조

- 가계부의 `LedgerEntry`는 `entryDate`, 원화 `amount`, 외화, 분할 그룹, 할부 및 환불·취소 원거래 ID를 보관한다. 기존 합계 쿼리는 `financiallyExcluded = false`인 행만 금액에 포함하고 삭제된 행은 제외한다. 건수는 원본 행 기준이다.
- `PlaceVisit.visitDate`는 nullable이며 `createdAt`을 방문일로 쓰면 안 된다. `RecordPlace.sourceTravelRecordId`는 여행에서 가져온 장소의 실제 연결 식별자다. 이름·날짜만 같은 항목은 합치지 않는다.
- 여행은 `TravelPlan.startDate`와 `endDate`가 nullable이다. `TravelExpenseRecord.expenseDate`와 `TravelRouteSegment.routeDate`는 별도 날짜를 가진다. 여행 기간이 없어도 이 날짜가 있는 기록은 조회해야 한다.
- 사진 메타데이터 도구는 클라이언트에서 EXIF 촬영 시각을 읽어 입력 보조에 활용할 수 있지만, 현재 `PlacePhoto`와 `TravelMediaAsset`에는 사진별 촬영일을 통합 달력에서 일관되게 조회할 저장 필드가 없다. 달력은 사진 업로드일이나 추출 시각을 촬영일로 취급하지 않고 연결된 방문·여행 기록 날짜를 사용한다.
- `TravelPlanShare`에는 수신자가 있으며, 기록 지도에도 별도 공유 모델과 접근 경로가 있다. 선택 설정에 남아 있는 ID만으로 접근을 허용하지 말고 조회 시마다 원본 권한을 검증한다. 공유 여행 접근과 개인 가계부 접근은 별개다.
- 운영 기본값에서 Flyway가 비활성화되고 Hibernate `ddl-auto`는 `update`다. 운영 마이그레이션을 임의 활성화하지 않는다. 기존 회원 탈퇴 정리 작업도 미커밋 상태이므로 일정과 공유 선택을 새 테이블로 만들 때 삭제·복구 정책과 함께 통합해야 한다.

## 구현 순서 및 안전 조건

1. 독립적인 월 요약 API를 출처별로 구현한다. 서버에서 사용자 권한 및 날짜 범위를 확인하고 기존 가계부 집계와 일치하는 금액·건수를 계산한다. 각 출처는 성공/실패를 구분하고 기록 지도 목록의 페이지 상한으로 월 전체가 잘리지 않도록 별도의 범위 집계를 둔다.
2. 날짜별 상세 API는 실제 원본 식별자를 사용해 분할 결제의 같은 날짜 수단만 묶고, 환불·취소와 연결 정보를 보존한다. 여행 전용 지출과 가계부 연결 거래는 합계를 분리한다. 시간 미입력과 실제 00:00은 기존 스키마만으로 구분하지 않는다.
3. 개인 일정과 공유 표시 선택은 계정별 서버 저장으로 추가한다. 날짜·시간 검증, 소유자 범위 CRUD, 탈퇴 정리, 복수 기기 동시 수정, 운영 DDL 및 Flyway 이력의 충돌을 검증한다. 선택한 공유 ID는 상세 조회 때마다 현재 원본 권한을 다시 확인한다.
4. 상단 메뉴에 월간 화면을 추가하고 출처별 실패·재시도, 날짜 없는 자료, 금액 숨기기, 필터, 원본 화면 이동을 연결한다. 주변 달의 칸은 보여도 월간 합계는 선택한 달만 사용한다.
5. 권한 철회·사용자 분리·월 경계·윤년·분할/환불/취소·대량 기록·동시 편집과 PC/모바일을 통합 테스트한 뒤 기존 가계부와 지도 회귀 테스트를 수행한다.

## 현재 구현과 남은 확인 사항

- `frontend/src/lib/integratedCalendarCore.js`의 날짜·분할 거래 계산을 월간 화면에 연결했다. 월 금액 합계는 기존 가계부와 같은 `financiallyExcluded` 조건을 쓰는 서버 집계이며, 표시 범위의 이웃 달은 합계에서 제외한다.
- 개인 일정은 별도 테이블과 계정별 API로 저장하며 버전 충돌을 검사한다. 월간 API는 제목·기간만 제공하고, 메모와 시간은 선택 날짜의 상세 요청으로 가져온다. 마이그레이션 `061`과 `062`가 추가되었지만 운영 DB 적용 여부는 확인하지 않았다.
- 공유받은 여행 전시와 수락된 여행 기록은 계정별 선택 설정에 저장하고 조회할 때마다 기존 공유 권한을 재검사한다. 기록 지도 공유는 최초 링크 소지 여부를 확인하고 토큰 원문을 보관하지 않는 계정별 증명 테이블을 사용한다. 선택 해제나 원본 공유 취소·만료 및 모음에서 장소 제거를 다시 확인하며 공유 여행의 금액은 개인 가계부 합계에 포함하지 않는다.
- 여행에서 가져온 장소는 실제 원본 ID로만 여행 기록과 연결하며 같은 장소의 별도 방문은 유지한다. 날짜 없는 방문과 기간 없는 여행은 원본 날짜를 임의로 만들지 않는다.
- 원본 가계부 거래 시트와 선택 행, 본인 장소 상세 및 여행·경로 화면으로 이동한다. 공유 여행은 기존 읽기 전용 전시를, 공유 장소는 기존 읽기 전용 지도와 선택 기록을 연다. 공유 지도 사진과 원본 화면은 계정의 선택 및 현재 모음 권한을 재검사한다.
- 서버 통합 테스트와 모의 API 기반 브라우저 테스트로 주요 기능 및 기존 가계부·기록 지도 회귀를 확인했다. 실제 운영 데이터·물리 기기·배포 후 동작은 확인하지 않았다. 브라우저 확대는 축소된 뷰포트로 근사 검증했으며 실제 브라우저 확대 조작과는 다르다.
