# 가계부 환불과 결제 취소

## 기록과 집계 기준

- **결제 취소**는 전액 취소되어 비용이 청구되지 않은 경우다. 원거래와 별도의 취소일 기록을 모두 보존하지만, 원거래와 취소 기록의 금액은 수입·지출 합계에서 제외한다. 따라서 원거래가 속한 이전 달의 지출도 갱신된다. 부분 결제 취소는 현재 지원하지 않는다.
- **환불**은 원 지출이 이미 발생한 뒤 금액을 돌려받는 경우다. 원 지출은 그대로 두고, 실제 수령액을 환불일의 수입으로 기록한다. 실제 수령액 = 환불 기준금액 − 차감액 + 추가 지급액이다. 원금 일부씩 여러 번 환불할 수 있으며 기준금액 합계는 원 지출을 넘을 수 없다. 원금을 넘는 별도 지급은 추가 지급액으로 입력한다.
- 모든 환불 입력은 원화 기준이다. 외화 원거래의 기준금액도 저장된 원화 환산액이며, 환불 수령 외화·환불일 환율은 별도로 계산하지 않는다. 수입 분류와 실제 수령 수단은 사용자가 지정한다.
- 실수로 등록한 처리는 되돌릴 수 있다. 되돌린 기록은 삭제하지 않고 합계에서 제외하며, 원거래와 연결해 이력을 표시한다. 처리 이력이 있는 원거래와 처리 기록은 일반 수정·삭제와 일괄 수정에서 보호한다.
- 날짜별 거래 건수에는 취소·되돌림 기록도 포함한다. 거래 목록과 검색에는 상태를 표시하며, 수입·지출 합계와 AI 지출 분석에서는 집계 제외 상태를 따른다.

예: 1월 카드 지출 100,000원에 대해 3월에 현금 93,000원을 받았고 10,000원이 차감되고 3,000원이 추가 지급됐다면, 1월 지출 100,000원은 유지하고 3월 수입 93,000원과 현금 수령 기록을 남긴다. 전액 결제 취소라면 1월 지출은 0원으로 바뀌고 취소일에 별도 기록이 남는다.

## 안전 경계와 제한

- 사용자 계정을 먼저 잠그고 원거래도 잠근 상태에서 기록한다. 사용자별 요청 키로 같은 요청의 재전송을 중복 처리하지 않는다. 다른 사용자의 거래와 분류·수단은 참조할 수 없다.
- 환불이 남아 있는 원거래에 전액 결제 취소를 중복 적용하지 않는다. 처리일은 원거래일 이전일 수 없고, 차감 후 실제 수령액이 음수인 경우는 지원하지 않는다.
- 이전에 다른 사용자에게 공유된 독립 거래는 자동으로 변경하지 않는다. 조정 기록 자체와 취소된 원거래는 일반 공유를 차단한다.
- 여행 기록에 연결된 원거래의 결제 취소는 여행 지출과 불일치하지 않도록 차단한다. 환불은 가계부에 기록되지만 기존 여행 지출은 자동 변경하지 않는다.
- 기존 CSV 형식에는 조정 상태와 원거래 연결을 보존할 칼럼이 없다. 재가져오기 때 취소된 지출이 활성 거래로 바뀌는 문제를 막기 위해 집계 제외 기록과 0원 기록은 CSV에서 제외한다. 환불은 일반 수입으로 내보내며 원거래 연결은 CSV에 보존되지 않는다.
- 스키마 마이그레이션 `V20261030_033_1`이 필요하다. 기존 거래는 집계 포함 상태로 유지된다. 새 프런트와 백엔드·마이그레이션을 함께 배포해야 하며, 운영 배포와 실제 MariaDB 검증은 별도다.
