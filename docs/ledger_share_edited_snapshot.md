# 거래 내용 수정 공유

작성일: 2026-10-15

## 사용 방법

1. 작성한 거래 내역에서 **공유**를 누릅니다.
2. 기본값인 **원본 그대로 공유**, 또는 **내용을 수정해서 공유**를 선택합니다.
3. 수정 공유에서는 제목, 금액, 날짜·시간, 수입·지출, 분류, 결제수단, 거래 메모를 수정합니다. 외화 거래는 외화 금액과 적용 환율을 입력합니다.
4. 공유 그룹과 받는 사람을 선택합니다. 별도의 공유 메모도 작성할 수 있습니다.
5. 상대방이 내용을 확인하고 자신의 분류·결제수단으로 승인하면 상대방 소유의 거래가 생성됩니다.

원본 거래는 바뀌지 않습니다. **원본 내용으로 되돌리기**는 공유 폼만 초기화하며, 원본 그대로 공유로 전환하면 수정 중인 내용은 전송하지 않습니다. 실패한 전송은 작성 내용과 선택을 유지합니다.

## 저장·권한 규칙

- 기존 `POST /api/record-shares` 요청에 선택 필드 `ledgerOverride`를 추가했습니다. 원본 공유는 이 필드를 생략합니다.
- `ledgerOverride`는 변경할 필드만 담는 패치가 아니라, 공유할 거래 전체를 담는 `LedgerEntryRequest`입니다. 중첩 필드 검증도 수행합니다.
- 수정 공유는 저장·병합되지 않는 임시 거래 객체로 검증한 후 기존 공유 스냅샷 필드에 저장합니다. 원본 엔티티, 변경 이력, 수입용 결제수단을 생성·수정하지 않습니다.
- 원본 소유권, 공유 그룹 접근권한, 수신자, 발신자 소유 분류·결제수단을 서버에서 확인합니다. 수신자 승인 때는 수신자 소유 분류·결제수단으로 검증합니다.
- 공유 메모는 거래 메모와 별도입니다. 수정 공유에도 동일하게 적용됩니다.
- 여행 연결 ID는 수정 공유본과 수신자 거래에 복사하지 않습니다. 여행 공유는 기존 읽기 전용 흐름을 유지합니다.
- 외화 수정 공유에는 양수 적용 환율이 필요합니다. 공유 처리 중 외부 환율 조회를 하지 않습니다.
- 동일한 수정 요청 재시도는 중복 생성하지 않습니다. 기존 승인 대기 내역과 다른 내용을 보내려면 보낸 요청을 취소한 뒤 다시 공유합니다. 이미 승인된 거래를 덮어쓰지 않습니다.
- 기존 스냅샷 컬럼을 사용하므로 DB 마이그레이션이나 새 환경변수는 필요하지 않습니다.

## 검증

- 프런트 단위 테스트: 27건 통과.
- 프런트 운영 빌드: 성공.
- 공유·거래·정기결제·분류 백엔드 회귀 테스트: 73건 통과.
- 격리 H2 통합 테스트: HTTP 요청별 트랜잭션 종료 후 원본 보존, 수정 스냅샷 조회·승인, 수신자 소유 분류 적용, 재시도·취소 후 재공유, 잘못된 입력·타인 분류 거부, 기존 API 호환성을 확인했습니다.
- 공유 브라우저 테스트: 데스크톱 1440×900 / 모바일 390×844에서 34건 통과. 수정 공유 폼·전송 버튼의 라이트/다크 테마 표시와 가로 넘침도 확인했습니다.
- 테스트는 운영 데이터가 아닌 H2 테스트 DB 또는 모의 API를 사용했습니다. 브라우저 테스트는 외부 네트워크 요청을 차단합니다.
- 시크릿 검사 및 변경 파일 공백 검사 통과. 기존 다른 작업 파일은 수정하지 않았습니다.
