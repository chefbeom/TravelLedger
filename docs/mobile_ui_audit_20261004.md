# 모바일 화면 재점검 — 2026-10-04

모바일에서 실제 사용을 방해하는 문제를 재현했다. 우선순위는 가계부 버튼의 터치 가로채기, 가로 화면 거래 금액 가림, 지도 핀의 터치 가로채기, 밝은 테마의 글자 대비다. 기존 모바일 테스트의 통과 결과만으로 전체 화면 사용성을 정상으로 판단할 수 없다.

서비스 소스는 수정하지 않았다. 이 문서와 진단 스크립트·측정 JSON·화면 캡처만 추가했다.

## 검증 범위와 증거

- Chromium 모바일·터치 에뮬레이션에서 320×640, 360×740, 390×844, 412×915, 844×390, 390×440을 확인했다.
- 390×440은 화면 높이가 줄었을 때의 경계 조건이다. 실제 모바일 키보드가 열린 상태를 검증한 것은 아니다.
- 가계부는 실제 App 및 HouseholdWorkspace 화면에 테스트용 로그인·거래·분류 API 응답을 연결했다. 실제 서버에 거래를 저장하거나 계정을 변경하지 않았다.
- 개인 지도는 여섯 크기, 공유 지도는 390×844와 844×390에서 실제 Vue 컴포넌트를 열었다. 사진과 위치는 합성 데이터이며 외부 지도 타일 요청은 차단했다.
- 지도 애니메이션 뒤 1.8초를 기다린 후 위치와 가림을 측정했다. 가려진 핀은 해당 상태를 기록한 뒤 진단용 click 이벤트로 정보창을 열어 후속 화면을 측정했다. 이 후속 측정을 정상 터치 성공으로 계산하지 않았다.
- 최종 진단의 여섯 크기에서 페이지 JavaScript 오류는 없었다. 이는 UI 가림이나 터치 가능 여부가 정상이라는 의미는 아니다.
- 실제 운영 로그인·데이터·지도 타일 로딩, iOS Safari, Android 실기기, 운영체제 키보드는 이번 검증 범위에 포함하지 않았다.

### 1. 가계부 입력 버튼을 덮는 플로팅 조작부

390×844에서 ‘모바일·데스크톱·테마’ 조작부는 상단의 고정 영역에 있고, ‘위·아래·이력’은 오른쪽 하단의 52px 버튼 세 개로 구성된다. 입력 화면은 이 영역을 피하지 않는다.

날짜 행이 하단으로 올라오도록 스크롤한 뒤 각 버튼 중심에 `elementFromPoint`를 실행한 결과:

- ‘입력 설정’의 중심 → ‘데스크톱’ 조작 버튼
- ‘오늘’의 중심 → ‘위’ 조작 버튼
- ‘다음날’의 중심 → ‘아래’ 조작 버튼

이는 단순히 정보가 겹쳐 보이는 것을 넘어 다른 동작이 실행될 수 있는 문제다.

### 2. 가로 화면 모드 선택과 거래 시트의 가림

844×390으로 처음 접근하면 `max-width: 760px` 조건을 벗어나 데스크톱 모드가 선택된다. 반면 390×844에서 시작한 화면을 844×390으로 회전시키면 기존 모바일 모드가 유지된다. 같은 크기에서 접속 경로에 따라 다른 화면이 나타난다.

새로 접근한 가로 화면의 거래 시트는 다음과 같다.

- 표 표시 영역: 760px / 실제 내용: 847px
- 가로 overflow: `hidden`
- 금액 칸: x=603.59, 너비=86.38 → 오른쪽=689.97
- 고정 작업 열: x=666.88 → 금액 칸과 약 23.1px 겹침
- 메모 칸: x=689.97, 너비=64.17 → 작업 열의 범위 안에 들어감

캡처에서 ₩12,000의 뒷부분과 메모가 가려진다. 모바일 모드를 유지한 회전 화면은 카드 형태이며 표시 영역과 내용 너비가 각각 776px로 일치한다.

### 3. 지도 조작부와 핀·팝업의 충돌

날짜 선택 후 지도가 안정된 상태에서 핀 중심의 터치 대상이 개인 지도 360·390px에서는 `.travel-map__toolbar`, 공유 지도 가로 화면에서도 조작 패널로 확인됐다. 실제 터치 시도에서도 패널이 이벤트를 가로챘다.

전체보기는 사방 40px의 고정 여백만 사용한다. 화면 하단·우측을 차지하는 조작 패널과 사진 미리보기의 실제 크기를 반영하지 않는다. 사진 선택 후 중심 이동과 팝업 배치 역시 모든 화면에서 이 영역을 피하지 못한다.

팝업 가림 수치:

- 320×640: 팝업 상단 y=135.9 / 조작 패널 하단 y=161.6 → 약 25.7px 겹침
- 390×440: 팝업 상단 y=35.9 / 조작 패널 하단 y=113.6 → 약 77.7px 겹침
- 844×390: 팝업 x=285~559 / 조작 패널 x=468~828 → 오른쪽 약 91px가 패널 영역과 겹침
- 390×844의 안정된 팝업은 패널과 겹치지 않았다. 클릭 직후 이동 중 화면의 일시적 가림은 지속적인 가림과 구분했다.

원인 위치: [전체보기의 고정 여백](C:/project/calen/frontend/src/components/TravelMyMapClusterPanel.vue:715), [플로팅 패널 위치](C:/project/calen/frontend/src/style.css:37512), [미리보기와 패널의 모바일 위치](C:/project/calen/frontend/src/style.css:38271).

수정 방향: 패널·미리보기가 차지하는 영역을 측정해 지도의 사용 가능한 영역을 계산하고, 전체보기·핀 중심 이동·팝업 위치에 동일한 여백을 적용한다. 모바일에서는 조작 패널을 접는 기능도 필요하다.

### 4. 테마 규칙 충돌로 인한 글자 실종·낮은 대비

실제 터치 이벤트로 ‘달력 가계부’를 선택하고 350ms를 기다린 뒤에도 밝은 테마에서 hover 상태가 유지됐다. 글자와 배경이 모두 `rgb(218, 215, 205)`로 확인됐다. 포인터를 옮기고 상태가 해제되면 배경은 `rgb(88, 129, 87)`로 돌아왔다.

일반 버튼의 hover 규칙은 배경만 바꾸고, 선택 버튼의 글자 규칙은 그대로 유지한다. 두 규칙의 우선순위가 충돌해 터치 기기에도 글자가 보이지 않는 상태가 남는다.

지도는 밝은 테마에서도 조작 패널 배경을 `rgba(15, 23, 42, 0.94)`로 고정한다. ‘지도 확대’ 글자는 `rgb(62, 80, 72)`, 줌 숫자는 `rgb(52, 78, 65)`로 표시되어 어두운 배경 위에서 읽기 어렵다. 이 문제는 버튼 위치의 문제가 아니라 테마 규칙과 고정 배경의 불일치다.

원인 위치: [일반 버튼 hover와 선택 버튼 규칙](C:/project/calen/frontend/src/style.css:33683), [지도 패널의 고정 어두운 배경](C:/project/calen/frontend/src/style.css:37512).

수정 방향: 선택·hover·focus·disabled 상태의 배경과 글자색을 함께 정의하고, 터치 기기에서 일반 hover가 선택 상태를 덮지 않도록 한다. 지도 패널도 동일한 테마 변수를 사용한다.

### 5. 모바일 지도 조작 패널의 과도한 내부 스크롤

미리보기를 열면 패널 높이가 `24dvh`로 제한된다. 테스트 데이터에서 내용 높이는 558px인데 390×844에서는 실제 표시 높이가 약 201px이다. 날짜·재생·속도·경로 조절을 한 번에 볼 수 없다.

속도 슬라이더에 포커스를 주면 패널 내부 스크롤이 약 286px 이동한다. 지도 확대·전체보기·날짜 선택 등 상단 조작부를 다시 사용하려면 작은 패널 안에서 역방향으로 스크롤해야 한다. 390×440에서는 표시 공간이 약 104px까지 줄어든다.

원인 위치: [미리보기 상태의 24dvh 제한](C:/project/calen/frontend/src/style.css:38281), [모바일 전체 화면의 32dvh 제한](C:/project/calen/frontend/src/style.css:37770).

수정 방향: 날짜·재생·속도는 짧은 기본 조작부로 유지하고, 경로·설명·고급 설정은 펼침 영역으로 옮긴다. 필수 버튼을 작은 스크롤 상자 안에 감추지 않는다.

### 6. 낮은 화면의 거래 시트와 긴 메모

390×440에서 거래 시트 헤더는 최대 약 185px인데 내용은 266px이다. ‘전체·수입·지출’, 시간 정렬 버튼 일부가 헤더 스크롤 영역 밖에 위치하고, 버튼 중심에는 거래 시트의 다른 영역이 잡힌다. 헤더를 따로 스크롤하면 접근할 수 있지만 바로 보이지 않는다.

390×844에서는 헤더가 약 266px를 차지한다. 긴 메모 8건을 넣으면 카드 목록의 스크롤 높이는 약 5,141px이며, 첫 거래의 작업 버튼도 메모 아래에 위치한다. 수정·공유·삭제가 가로로 잘리지는 않았지만 내용을 확인하고 작업하기까지 많은 세로 이동이 필요하다.

## 추가 관찰과 정상 확인 범위

- 네 가지 세로 너비에서 빠른 거래 입력과 정기결제 폼의 입력칸 자체가 가로로 넘치거나 잘리는 현상은 재현되지 않았다. 텍스트 입력칸의 글자 크기는 16px 미만으로 측정되지 않았다.
- 거래 시트의 수정·공유·삭제 버튼은 세로 모바일 카드 안에 가로로 들어갔다. 긴 메모 때문에 아래쪽으로 밀리는 문제와 구분한다.
- 390×844의 초기 화면은 상단 메뉴·조회 기준일·기능 탭이 거의 첫 화면을 채운다. 기본 구성에서 달력 자체가 문서 상단으로부터 약 2,399px 아래에 있어 달력 화면을 열어도 바로 달력을 보지 못한다. 상단 기능과 빠른 입력의 접기·진입 동선 개선이 필요하다.
- 날짜 행의 ‘오늘’ 버튼은 너비가 약 23px로 매우 작다.
- 사진 상세 창은 후속 진단 상태에서 열렸고 오류는 없었다. 실제 사진 비율·원본 로딩 지연과 운영체제 키보드는 별도 실기기 검증이 필요하다.

## 수정 순서

1. 가계부의 터치 가로채기와 거래 금액 가림을 먼저 해소한다.
2. 지도에서 패널·미리보기를 피하는 지도 영역 계산을 통일한다.
3. 테마 및 버튼 상태 규칙을 정리해 동일색 글자와 낮은 대비를 없앤다.
4. 조작부·시트 헤더·긴 메모·상단 기능 영역을 모바일에서 짧고 접을 수 있게 구성한다.
5. 이번에 확인한 조건을 회귀 검사에 포함하고 운영 데이터·실기기·키보드 상태를 검증한다.

기존 테스트의 문서 가로 overflow 검사와 개별 버튼 클릭 검사는 표 안쪽의 금액 가림, 외부 고정 버튼과의 충돌, 접속 방향에 따른 모드 변화, 터치 후 hover 상태를 충분히 검증하지 못한다. 지도 검증도 패널이 차지하는 공간을 제외한 핀·팝업 가림 조건을 추가해야 한다.
