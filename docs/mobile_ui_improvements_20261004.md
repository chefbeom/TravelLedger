# 모바일 UI 개선 — 2026-10-04

## 목표와 범위

[재점검 보고서](C:/project/calen/docs/mobile_ui_audit_20261004.md)의 우선 문제를 기준으로 다음 목표를 설정했다.

1. 가계부 입력 버튼을 다른 고정 버튼이 덮지 않도록 한다.
2. 가로 접속·회전·수동 보기 모드에서도 거래 금액과 작업 버튼을 확인할 수 있도록 한다.
3. 개인·공유 지도에서 핀과 팝업이 조작부·미리보기에 가려지지 않도록 한다.
4. 선택 상태와 밝은/어두운 테마의 글자 대비를 개선한다.
5. 좁거나 낮은 화면에서 필수 조작부를 짧게 구성하고 터치 회귀 검사를 추가한다.

백엔드·인증·DB·거래 저장 API는 변경하지 않았다. 초기 수정·검증 단계에서는 커밋·푸시를 수행하지 않았으며, 이후 사용자의 별도 요청에 따라 소스·테스트·보고서를 커밋 대상으로 정리했다.

## 구현한 내용

### 가계부와 화면 모드

- 모바일의 보기/테마 전환은 문서 흐름 안에 배치했다. 가계부의 위로·아래로·이력 도구는 헤더에 넣고 모바일 고정 도구는 숨겨 입력 버튼의 터치 가로채기를 제거했다.
- 모바일에서 펫 도크도 문서 흐름 안에 두어 입력칸을 덮지 않도록 했다. 데스크톱의 기존 플로팅 배치는 유지한다.
- 너비 760px 이하 또는 1100px 이하의 터치 기기는 자동 모바일 모드를 사용한다. 화면 변경을 감지하고, 명시적으로 선택한 모바일/데스크톱 설정은 보존한다. ‘자동’ 버튼으로 수동 설정을 해제할 수 있다.
- 거래 시트는 실제 컨테이너 너비가 1000px 이하이면 카드 형태로 표시한다. 넓은 표의 작업 열 고정을 제거하고 가로 스크롤을 허용해 금액·메모를 덮지 않도록 했다.
- 필터·정렬 버튼 다섯 개는 선택 목록 두 개로 줄였다. 긴 메모는 두 줄 요약 후 펼쳐서 읽도록 했다. 수정·공유·삭제는 세 칸을 유지한다.
- 거래 시트는 body로 Teleport되는 경우까지 스타일을 적용했다. 오래된 반투명 카드 배경을 테마 패널 색으로 바꾸고 삭제 버튼의 배경·글자를 함께 지정했다.
- 날짜의 오늘/전날/다음날 버튼의 터치 영역을 늘렸다.

### 개인 지도와 공유 지도

- 모바일 전체 화면은 필수 조작부를 위쪽 행에 두고, 그 아래 실제 지도 영역을 할당한다. 확대·축소·전체보기·나가기·날짜·재생·속도를 기본 상태에서 바로 사용할 수 있다.
- 경로 따라가기·클러스터 안내·Esc 안내는 ‘설정’ 안으로 접었다. 재생 속도는 기존 1~5초 드래그바를 유지한다.
- 조작부와 미리보기의 실제 크기를 측정해 가장 넓게 남는 지도 영역을 계산한다. 전체보기, 선택 핀 중심, 여정 이동, 먼 거리 이동의 축소 계산에서 같은 영역을 사용한다.
- 정보 팝업은 남은 공간에 맞춰 높이를 제한하고 내부 스크롤을 제공한다. Leaflet의 팝업 바깥 여백까지 반영한다. 지도 크기·설정·미리보기 크기가 바뀌면 다시 계산한다.
- 리사이즈로 발생한 다른 `moveend` 이벤트를 여정 이동 완료로 오인하지 않도록 요청한 중심·줌 도착을 확인한다. 사진 카드 유지 간격의 조기 시작을 방지한다.
- 미리보기 크기 변경을 관찰하되 같은 크기를 반복 설정하지 않아 반응성 루프를 방지한다. 제거된 미리보기의 크기 관찰도 해제한다.
- 조작 패널은 테마 변수를 사용한다. 투명 SVG 핀, 썸네일 클러스터, 사진 상세, Esc 단계별 닫기, 미리보기 크기 조절은 유지한다.

## 검증

- 단위 검사: 18개 통과.
- 프런트엔드 배포 빌드: 성공.
- 전체 브라우저 회귀 검사: 122개 통과, 24개 건너뜀, 실패 0개(146개 실행 목록). 운영 계정·데이터가 필요한 검사와 데스크톱 프로젝트에 해당하지 않는 모바일 전용 검사는 건너뛰었다.
- 신규 회귀 검사: 6가지 화면 크기의 가계부·개인 지도·공유 지도와 자동/수동 모드 전환, 총 19개 시나리오. 두 프로젝트 설정에서 반복 실행한다.
- 크기: 320×640, 360×740, 390×844, 412×915, 844×390, 390×440.
- 실제 터치 `tap()`과 `elementFromPoint`로 덮임을 검사한다. 가려진 버튼에 합성 click 이벤트를 보내 테스트를 통과시키지 않는다.
- 거래 금액 전체 표시, 긴 메모 펼치기, 작업 버튼 세 개, 필터·정렬, 핀 터치, 팝업 범위, 설정 열기/닫기, 기본 조작부 내부 스크롤, 양쪽 테마의 글자 대비를 확인한다.
- 버튼 대비는 투명 버튼 뒤의 실제 배경을 합성해 4.5:1 이상을 확인한다. 테마 전환 애니메이션이 안정된 뒤 측정한다.
- 별도 진단에서 여섯 크기 모두 가계부 입력·거래 시트·정기결제·지도 조작부의 가로 잘림과 JavaScript 오류가 재현되지 않았다. 개인 지도 여섯 크기와 공유 지도 두 크기의 핀은 합성 click 없이 열렸다.
- Windows에서 테스트 동영상 파일을 Vite가 감시하다 종료되는 `EBUSY`도 발견해 테스트 산출물 폴더를 감시 대상에서 제외했다.

## 검증 한계와 후속 확인

- 실제 iOS Safari·Android 실기기, 운영체제 키보드, 브라우저 주소창 크기 변화, 확대된 시스템 글꼴은 별도 확인해야 한다. 390×440 검사는 키보드 테스트가 아니라 낮은 화면의 경계 조건이다.
- 브라우저 검사는 합성 거래·사진·계정 API 응답을 사용하며 운영 데이터 저장이나 실제 로그인은 수행하지 않았다. 외부 지도 타일 요청을 차단했으므로 실제 타일 로딩 지연·네트워크 품질을 보증하지 않는다.
- 운영 계정·데이터가 필요한 검사는 건너뛴 항목으로 구분한다. 통과로 계산하지 않는다.
- 모바일에서 처음 달력에 도달하기까지 상단 정보와 빠른 입력이 길게 이어지는 동선은 여전히 별도의 UX 개선 후보다. 이번 수정은 핵심 조작의 가림·잘림과 불일치 해결에 집중했다.
