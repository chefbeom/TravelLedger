# 성능 개선 운영 적용 안내

2026-10-03 구현 기준. [구현 및 검증 기록](/C:/project/calen/docs/performance_improvement_progress.md)을 함께 확인한다. 이 문서는 운영 적용 절차이며, 이번 작업에서 운영 서버를 배포하거나 데이터를 변경하지 않았다.

## 1. DB 변경을 먼저 검증한다

신규 Flyway 파일은 `V20261003_022`부터 `V20261003_029`까지다.

| 버전 | 내용 |
|---|---|
| 022 | 드라이브 소유자·부모 폴더·최근 목록 인덱스 |
| 023 | 서버 간 작업 소유권 테이블 |
| 024 | 이미지 분석 입력 프롬프트, 소유자별 요청 ID 유일 제약 |
| 025 | 일반 AI 분석 복구용 프롬프트 |
| 026 | 엑셀 AI 작업 입력·결과 테이블 |
| 027 | AI 작업의 동시 수정 버전 |
| 028 | 사진 묶음 갱신 요청·세대 번호 테이블 |
| 029 | 사진 묶음 멤버 조회 인덱스 |

개발 테스트는 H2에서 엔티티와 조회를 검증했다. MariaDB용 마이그레이션은 별도 테스트 DB에서 기존 데이터 복사본으로 실행하고, 기존 마이그레이션 이력과 인덱스 이름을 확인해야 한다. 현재 `DB_MIGRATION_ENABLED` 기본값은 false이므로 운영에서 사용하는 스키마 관리 방식에 맞게 적용한다. Hibernate 자동 갱신만으로 마이그레이션이 모두 실행됐다고 판단하면 안 된다.

024는 동일 소유자의 중복된 기존 요청 ID 중 최신 행만 ID를 유지하고, 이전 행은 ID를 비운다. 분석 이력 자체를 삭제하지 않는다. 기존의 복구 입력이 없는 PROCESSING 작업은 재시도 안내와 함께 실패로 종료될 수 있다.

## 2. 여러 서버의 공유 설정을 맞춘다

모든 백엔드가 같은 MariaDB를 사용해야 작업 소유권과 제공자 추론 제한이 공유된다. 같은 모델 제공자에는 같은 provider·base URL 및 `APP_LEDGER_AI_MAX_CONCURRENT`를 설정한다. 다른 주소로 같은 실제 모델 서버를 가리키면 별도 제공자로 취급될 수 있다.

공유 세션은 `APP_SHARED_SESSION_ENABLED=true`로 선택한다. 기본값 false에서는 기존 로컬 세션을 사용한다. 활성화할 때 모든 서버의 `REDIS_STATE_*`와 `SESSION_SEAL_KEY`를 동일하게 설정한다. 기존 로컬 세션이 Redis로 자동 이관되지는 않으므로 전환 후 기존 사용자는 다시 로그인해야 할 수 있다. 로그인·2차 PIN·로그아웃을 두 서버를 번갈아 호출하며 확인한다.

공유 세션 Redis는 인증에 필요한 상태 저장소다. 선택적인 캐시 Redis와 장애 영향이 다르므로 세션 Redis 장애 시 로그인을 계속 유지한다고 가정하지 않는다. 세션 Redis의 연결·명령 제한 시간은 각각 3초다.

## 3. 기본 제한과 의미

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `APP_LEDGER_AI_MAX_CONCURRENT` | 1 | 같은 제공자의 동시 추론 수, 공유 DB 기준 |
| `APP_LEDGER_AI_MAX_WAITING` | 20 | 제공자 앞에서 대기할 요청 수, 인스턴스별 |
| `APP_LEDGER_AI_WAIT_TIMEOUT` | 30s | 로컬·공유 추론 슬롯을 기다릴 최대 시간 |
| `APP_LEDGER_AI_WORKERS` / `APP_LEDGER_AI_QUEUE_CAPACITY` | 1 / 100 | 일반·엑셀 AI 실행 풀과 대기 큐, 인스턴스별 |
| `LEDGER_OCR_WORKERS` / `LEDGER_OCR_QUEUE_CAPACITY` | 1 / 100 | 이미지 AI 실행 풀과 대기 큐, 인스턴스별 |
| `LEDGER_OCR_MAX_PENDING_PER_USER` | 5 | 이미지 AI 사용자별 접수 제한, 인스턴스별 |
| `APP_HTTP_ASYNC_WORKERS` / `APP_HTTP_ASYNC_QUEUE_CAPACITY` | 8 / 64 | 파일 스트리밍 실행 풀과 대기 큐 |
| `APP_HTTP_ASYNC_TIMEOUT_MILLIS` | 600000 | HTTP 비동기 응답 제한 시간, 밀리초 |
| `APP_HTTP_MAP_WORKERS` / `APP_HTTP_MAP_QUEUE_CAPACITY` | 4 / 32 | 지도 조회·갱신 대기 전용 실행 풀과 큐 |
| `DRIVE_MAX_ZIP_FILES` | 2000 | ZIP에 포함할 파일 수 |
| `DRIVE_MAX_ZIP_BYTES` | 2147483648 | ZIP 압축 전 입력 합계와 실제 읽은 바이트의 최대값 |
| `TRAVEL_REVERSE_GEOCODE_QUEUE_CAPACITY` | 16 | 외부 주소 조회의 대기 큐 |
| `APP_SHARED_SESSION_ENABLED` | false | Redis 공유 로그인 세션 사용 여부 |
| `APP_HTTP_METRICS_HISTOGRAM_ENABLED` | true | HTTP 응답 시간 분포 수집 |

일반 AI 사용자별 진행 수는 인스턴스별 5개다. 엑셀 사용자별 PROCESSING 작업 수는 DB 기준 5개다. 사진 갱신은 인스턴스별 워커 1개·큐 64개이며 같은 사용자의 요청을 합친다. 로컬 미디어·주소 캐시는 최대 4,096개다.

실행 풀의 워커는 실제로 일을 수행하는 스레드다. 큐는 아직 실행하지 못한 작업을 기다리게 하는 공간이다. 큐를 키워도 완료 처리량이 늘지는 않으며 대기 시간이 길어질 수 있다. 제한 초과는 429 또는 503으로 응답하고 해당 처리 경로에서 제공하는 재시도 안내를 사용한다.

일반·이미지·엑셀·사진 작업 소유권은 기본 2분이고 살아 있는 서버가 15초마다 갱신한다. 제공자 추론 슬롯은 30분 소유권을 사용한다. 미완료 작업 복구는 1분 주기로 실행한다. DB 장애나 비정상 종료 뒤 즉시 재실행된다고 가정하지 않는다. 제공자 슬롯은 기존 소유권 만료까지 기다릴 수 있다.

## 4. API 및 화면 확인

엑셀 AI는 `POST /api/entries/imports/excel/preview-ai/jobs`로 작업 ID를 접수하고 `GET /api/entries/imports/excel/preview-ai/jobs/{jobId}`로 상태와 결과를 읽는다. 화면은 2초 간격으로 조회하며 최대 30분을 기다린다. 대기 제한을 넘겨도 서버 작업은 계속될 수 있다. 기존 동기 미리보기 API는 호환용으로 유지한다.

이미지 분석은 기존 멀티모달 LLM을 사용한다. MinIO 저장소 참조를 큐에 넣으므로 큰 이미지가 대기할 때 원본 전체를 JVM에 계속 보관하지 않는다. 임시 파일 대체 경로는 서버 재시작 복구를 지원하지 않으므로 운영에서는 MinIO 원본 저장과 읽기를 확인한다.

사진 업로드·삭제는 갱신 요청을 DB 변경과 함께 기록한다. 계산은 별도 워커에서 수행한다. 최신 사진 묶음이 필요한 지도 조회는 최대 30초 기다리고, 아직 완료되지 않으면 재조회 안내를 반환할 수 있다. 기존 데이터가 많은 계정의 첫 지도 조회는 초기 갱신 비용이 든다.

파일 전송은 헤더와 전송이 시작된 뒤 실패할 수 있다. 이 경우 중간 전송 오류를 일반 JSON 오류 응답으로 바꿀 수 없다. 공개 다운로드의 접근 기록은 전송 시작 시점에 남으므로 접근 성공 횟수를 전체 파일 전송 완료 횟수로 해석하지 않는다.

## 5. 실제 부하 검증

운영과 같은 MariaDB·Redis·MinIO·모델 구성의 별도 환경에서 변경 전후를 비교한다. AI 요청이 몰린 동안 일반 가계부 조회, 큰 이미지 대기, 파일·ZIP 동시 다운로드, 사진 1만 장 계정의 변경과 지도 조회, 같은 좌표의 주소 요청, 캐시 만료 직후 조회, 두 서버의 재시작을 확인한다.

HTTP p95/p99는 전체 요청의 95%/99%가 그 시간 안에 끝났다는 뜻이다. 응답 시간 외에 오류율, DB 연결 사용·대기, SQL 실행 시간·읽은 행 수, JVM 힙과 메모리 정리(GC) 지연, 큐 대기·모델 추론 시간을 따로 측정한다. 네트워크·디스크·GPU 포화도 함께 확인한다.

이번 코드 테스트는 기능 회귀와 동시성 방어를 검증한다. 운영 처리량 향상 배수나 최대 동시 사용자 수를 측정한 결과는 아니다. 화면 범위별 지도 조회, 큰 포트폴리오의 단계별 로딩, 썸네일·CDN, 사전 집계 및 DB·스토리지 분리는 이 측정 결과를 기준으로 추가 결정한다.

엑셀 완료 결과의 자동 삭제는 활성화하지 않았다. 보존 기간은 별도의 명시적인 운영 정책 결정 사항이다.
