# 성능 개선 구현 및 검증 기록

기준일: 2026-10-03. [개선 전 검토](/C:/project/calen/docs/high_traffic_performance_review.md)의 주요 병목을 수정했다. 기존 사용자 변경인 `frontend/src/App.vue`, `frontend/src/components/MainDashboardWorkspace.vue`는 보존했다. 운영 적용 방법은 [설정 및 검증 안내](/C:/project/calen/docs/performance_improvement_deployment.md)에 정리했다.

이미지 OCR은 **멀티모달 LLM에 이미지를 직접 보내 문자와 거래 항목을 추출하는 기존 방식**을 유지한다. PaddleOCR를 연결하거나 분석 모델을 바꾸지 않았다.

## 수정 사항과 이유

| 영역 | 수정 | 줄이는 비용 |
|---|---|---|
| AI 제공자 대기 | 제공자·주소별 동시 추론, 대기 인원, 대기 시간을 제한. 포화 시 429와 재시도 시간을 반환. DB 작업 소유권으로 서버 간 추론 슬롯 공유 | 제한 없는 대기와 모델 서버 과부하 |
| 엑셀 AI | DB 조회와 엑셀 읽기를 먼저 끝내고 모델 호출. 작업 ID를 반환하는 API와 화면 상태 조회 추가. 준비한 입력을 DB에 보관하고 큐에는 ID만 저장 | 오래 점유되는 DB 연결·HTTP 요청 처리 스레드 |
| 이미지 AI | 접수 때 원본을 저장소 또는 임시 파일에 저장. 큐에는 참조만 보관하고 실행할 때 원본을 읽음. 사용자별 접수 제한, 취소·거절·완료 자원 정리 | 대기열의 원본 이미지 메모리 누적 |
| AI 재시작·중복 | 일반·이미지·엑셀 작업 입력 저장 및 주기적 복구. 복구 조회는 커서로 다음 페이지 진행하고 다음 주기에도 이어서 조회. 이미지 요청 ID 유일 제약, 일반 분석의 서버 간 접수 잠금, 작업 버전 검사 | 같은 작업의 중복 처리와 취소 후 완료 상태 덮어쓰기 |
| 파일·ZIP | 일반·공유·공개 다운로드를 스트리밍. ZIP 파일 수·원본 합계 및 실제 읽은 바이트 제한, HTTP 전송 실행 풀 제한 | 파일 전체를 메모리에 담는 비용 |
| 드라이브 조회 | 홈 집계, 최근 파일, 사진 필터·정렬·제한을 SQL로 처리. 부모 폴더 조건 조회와 하위 폴더 ID 일괄 조회, 인덱스 추가 | 전체 파일 조회·Java 필터링·반복 트리 조회 |
| 사진 묶음 계산 | 지구 중심 3차원 격자로 가까운 후보만 비교. 변경된 묶음·멤버만 저장. 업로드 트랜잭션에는 갱신 요청만 기록하고 별도 워커가 계산 | 거리 중첩 비교, 불필요한 재저장, 긴 쓰기 트랜잭션 |
| 사진 동시 변경 | 사진 변경과 갱신 요청을 같은 트랜잭션에 기록. 계산 전후 세대 번호 비교로 오래된 결과 폐기. 갱신 요청 병합·재시작 복구·수동 대표 사진 변경 보호 | 동시 업로드 결과 누락과 이전 계산의 덮어쓰기 |
| 지도 | 인접 핀 후보를 DB에서 범위·거리·개수 제한. 개요는 가벼운 핀 필드만 조회. 사진 상세는 선택한 클러스터의 요청 페이지를 SQL로 읽음. 지도 대기는 전용 제한 풀로 분리 | 사용자 전체 사진 상세 구성·전체 거리 정렬·HTTP 스레드 대기 |
| 주소 조회 | 전용 워커·제한 큐, 같은 좌표 요청 병합, 요청별 취소 격리, 외부 호출 시간 제한. 모든 서버가 제공자 호출 시작 간격 공유 | 중복 외부 호출과 HTTP 스레드 대기 |
| 대시보드 | 제한된 기간의 일별 집계를 카드·달력·월 비교에 재사용. 관련 가계부 repository 조회 경로 9개에서 4개로 감소 | 같은 가계부 데이터의 반복 집계 |
| 캐시·프런트 | 지도·여행·포트폴리오 캐시 미스 계산 병합, 커밋 후 무효화, 오래된 계산의 재등록 방지. 로컬 캐시 크기 제한·만료 정리. Redis 재연결 분리 및 오류 격리. 프런트 동시 GET 병합 | 만료 시 중복 계산, 장애 전파, 만료 항목 누적 |
| 서버 확장·반복 가계부 | Redis 공유 세션 선택 기능. DB 기반 작업 소유권과 15초 갱신. 반복 가계부를 100개 후보 조회·규칙별 짧은 트랜잭션과 DB 잠금으로 처리 | 서버 변경 시 세션 손실, 스케줄 작업 중복, 큰 배치 트랜잭션 |
| 설정·관측 | 실행 풀·큐·시간·ZIP 제한을 설정으로 노출, 예제 환경 파일·Compose 동기화. HTTP 지연 히스토그램 활성화 | 운영 제한 조정과 병목 관측의 어려움 |

'스트리밍'은 파일을 조금씩 읽어 즉시 전송하는 방식이다. '트랜잭션'은 DB 작업의 성공·취소를 묶는 단위다. '작업 소유권(lease)'은 일정 시간 동안 특정 서버만 작업하도록 하는 권리이며, 살아 있는 서버가 주기적으로 갱신한다. '세대 번호'는 사진 데이터가 몇 번째로 바뀌었는지를 나타내며, 계산 결과가 최신 입력에 대한 것인지 확인한다.

## 검증

- 관련 테스트 묶음 통과. 사진 계산 중 입력 변경 시 재계산·한 번만 저장, 갱신 요청의 롤백 및 커밋 후 실행, 캐시 오류 격리, 분산 접수와 복구 페이지 진행을 포함한다.
- 최종 백엔드 전체 테스트 382개 통과(실패·오류·스킵 0). SQL 사진 상세의 소유자 범위·대표/선택 사진 순서, 복구 시간 커서 및 다음 실행으로 이어지는 스캔, 로그인 사용자 정보의 공유 세션 직렬화를 포함한다.
- 프런트 단위 테스트 3개 통과, 프로덕션 빌드 통과.
- 백엔드 실제 배포 형식의 `bootWar` 빌드 통과.
- 환경 설정 동기화: application 변수 166개를 두 예제 파일·계약 문서에서 검사, 통과.
- 변경 파일 공백 검사 통과.
- 운영 Redis·MariaDB·MinIO·모델 서버를 연결한 통합 부하 테스트와 신규 MariaDB 마이그레이션 실적용은 수행하지 않았다.

## 적용 범위와 후속 측정

기본 AI 동시 추론 수 1은 유지한다. 병렬 추론이 빨라지는지는 GPU·모델·입력 크기에 따라 달라지므로 실제 처리 용량을 측정한 뒤 조정한다. 여러 서버는 같은 DB와 같은 제공자 제한을 사용해야 한다.

이미지 복구는 MinIO의 원본이 있어야 한다. 임시 파일만 사용한 작업은 서버 재시작 시 복구할 수 없어 실패로 종료한다. 작업 소유권과 버전 검사로 중복 저장을 방어하지만, 장애 순간 외부 모델 호출 자체의 정확히 한 번 실행까지 보장하지 않는다. 진행 중인 원격 추론의 실제 중단 여부도 모델 제공자에 달려 있다.

전체 지도·포트폴리오는 기존 화면 계약을 유지하므로 기록량에 비례한 응답 크기는 남는다. 공개 지도·공유 생성과 수동 대표 사진 변경 일부는 해당 데이터의 계산을 수행한다. 화면 범위별 지도 조회, 포트폴리오 단계별 로딩, 썸네일 전용 처리와 CDN, 날짜별 사전 집계는 실제 부하 측정에 따라 이어갈 확장 사항이다. 공간 격자도 극단적으로 밀집한 데이터에서 모든 거리 비교를 제거하지는 않는다.

엑셀 AI 완료 결과는 보관한다. 24시간 뒤 자동 삭제하는 보존 정책은 적용하지 않았다. 기존 일반 AI 이력의 별도 보존 설정은 유지한다.

운영 처리량·지연·힙 사용 개선 수치는 부하 테스트 전까지 확정하지 않는다. 데이터 마이그레이션과 공유 세션 활성화는 운영 적용 단계에서 확인한다.
