# 기록 지도 개편 목표

기존 여행 데이터·일정·경로·가계부·공유·재생은 원본을 유지한다. 새 기록 지도에서는 여행 생성 없이 장소를 저장하고, 같은 장소에 날짜별 방문 기록과 사진·메모를 남긴다.

- 장소와 모음은 다대다 관계다. 모음을 삭제하거나 장소를 모음에서 빼도 방문 기록과 사진은 유지된다.
- 방문 상태는 수동 표시 또는 방문 기록을 기준으로 계산한다. 날짜 없는 북마크는 여정 재생에 포함하지 않는다.
- 여행 장소 가져오기는 소유한 원본 여행 기록을 참조한다. 여행 원본을 변경하거나 복제하지 않는다.
- 공통 핀·썸네일·클러스터 및 사진 미리보기 컴포넌트를 재사용한다.
- 장소/날짜/모음 필터, 페이지별 장소 목록, 시간순 방문 재생을 제공한다.
- 모음 공유는 사용자가 명시적으로 생성한 읽기 전용 링크로 제한한다. 기본 공유는 장소 이름·좌표·방문 상태이며, 사진과 방문 메모는 별도 선택한다. 링크는 만료·취소가 가능하고 공개 응답은 캐시하지 않는다.
- 모든 저장·수정·삭제·사진 접근은 소유자 또는 유효한 모음 링크 범위로 검사한다. 비공개 원본 여행 미디어를 일반 공개 주소로 노출하지 않는다.
- 지도 개편은 recordmap 서비스에 구현하며 기존 TravelService의 책임을 늘리지 않는다.

검증: 사용자 간 접근 거부, CSRF, 모음 다중 연결 및 삭제 후 기록 보존, 사진 접근/공유 범위/취소, 방문·날짜 필터, 여행 참조 소유권, 기존 여행 회귀, 프런트 빌드와 재생 자료 처리.

## 구현 범위

- 상단 `기록·지도` → `일상 기록·장소 모음` / `여행·일정·경로`로 분리했다. 기존 여행 경로와 공개 공유 주소는 유지한다.
- 새 장소는 지도 클릭, 위치 검색, 현재 위치 또는 사진 EXIF 위치로 등록한다. 장소만 저장하거나 방문 날짜·사진·메모를 함께 저장할 수 있다.
- 같은 장소의 여러 방문을 별도로 저장하며, 장소는 여러 모음에 연결할 수 있다. 여행 장소 가져오기는 소유한 여행 기록 ID를 연결하고 날짜·사진은 원본에서 읽는다.
- 지도·목록·일상 기록에서 모음/방문 여부/날짜 조건을 적용한다. 장소는 페이지당 100개, 지도용 방문은 최근 200건, 연결된 여행 사진은 최대 1,000개이며 상세 방문 목록은 20건씩 조회한다. 재생은 현재 페이지/조회 범위의 날짜 있는 기록만 포함한다.
- 공통 지도 컴포넌트의 새 기능은 선택적 옵션이다. 새 모음 링크는 읽기 전용이고, 기존 개인정보 공개 해제 기능에서도 함께 종료한다.
- 사진 재생 간격은 1~5초다. 먼 장소로 이동할 때 먼저 두 위치가 보이도록 축소하고, 목적지 이동과 타일 로딩 대기 후 간격을 계산한다. 날짜 전환에는 3초 안내를 제공한다.
- 모음 삭제는 공유 링크와 모음 연결만 제거한다. 장소/방문/사진 삭제는 확인을 거치며 방문 기록이 남은 장소는 먼저 방문 기록을 정리해야 한다. 여행 원본은 삭제하지 않는다.

## 검증 상태 · 2026-10-13

- `frontend: npm run build`: 통과. 새 화면 및 공개 공유 라우트 포함 141개 모듈 빌드.
- `backend: gradlew compileJava compileTestJava`: 통과. 기존 deprecation/unchecked 경고 외 컴파일 오류 없음.
- 사용자의 명시적 테스트·검증 승인 후 격리된 H2 DB와 로컬 저장소에서 실행했다. 기존 여행/공유/개인정보 회귀를 포함한 백엔드 76개 테스트가 모두 통과했다. 새 통합 테스트 7개와 SQL 마이그레이션 테스트 1개는 권한/CSRF, 기본 비공개, 모음 삭제 후 보존, 만료·취소·멤버십 제거, 여행 참조/원본 삭제, 가짜 이미지 차단, 방문당 사진 20장 제한, 소유자 FK·여행 참조 중복 제약·조회 인덱스를 확인한다.
- 프런트 단위 테스트 22개 통과. 새 자료 변환 테스트 4개는 사진 그룹/ID 구분, 날짜 없는 북마크 재생 제외, 사진 없는 방문 재생, 시간순 정렬과 공유 응답 범위를 확인한다.
- Playwright 데스크톱(1440×900)/모바일(390×844) 화면 테스트 60개 모두 통과. 신규 기록 지도 16개와 기존 여행 지도 44개를 포함한다. 화면 테스트는 전용 루프백 서버/가상 API·사진으로 수행하며 외부 네트워크를 차단한다. 서버 실제 권한과 DB 저장은 별도 H2 통합 테스트로 검증했다. 이전 QA 자료는 다른 폴더에 보존했다.
- `verify-db-migrations.ps1`, `verify-public-share-authorization-contract.ps1`, `verify-privacy-control-contract.ps1`, `verify-service-decomposition-plan.ps1` 통과. 공유 검증 스크립트의 잘못된 상수명은 실제 URL 토큰 추출 사용부로 정정하고 누락된 로드맵의 스크립트 링크를 추가했다. 보안 검사와 런타임 권한 규칙은 완화하지 않았다.
- 운영 서버/DB/MinIO 변경, 커밋·푸시는 실행하지 않았다. 기존 미커밋 작업은 보존했다.
- 추가 코드 점검에서 사진 없는 장소가 공통 지도 렌더링/전체 범위 계산에 빠진 연결을 수정했다. 새 기록 지도만 옵션을 켜 기존 여행 표시 방식은 유지한다. 사진 EXIF/GPS 비동기 응답은 사용자의 직접 입력값을 덮어쓰지 않도록 처리했다.
- 브라우저 검증에서 모바일 전체화면의 펫 겹침과 지도 드래그 후 배경 탭 누락을 수정했다. 일시적인 위치 선택창은 줌 애니메이션을 끄는 선택적 옵션을 사용해 창 종료 후 Leaflet 지연 이벤트 오류를 방지한다. 본 지도 여정 이동과 기존 여행 기본 옵션은 유지한다. 공유 접근이 취소·만료되면 이전 지도와 열린 상세도 제거한다.
- 최종 화면 점검에서 모바일 장소 입력창의 가로 경계와 밝은 테마 검색 버튼의 글자 대비를 보완했다. 내부 지도 검색의 제출 이벤트가 장소 저장 폼으로 전달되지 않도록 분리했다. 외부 요청 대신 가상 위치 검색 결과를 사용해 좌표 반영·미저장 상태와 버튼 대비(4.5:1 이상)를 확인했고, 최종 60개 화면 테스트와 빌드를 다시 통과했다.

## 배포 전 확인

새 스키마는 `V20261013_033__record_map.sql`이다. 운영 Flyway 설정을 일괄 변경하지 말고 기존 DB 마이그레이션 절차에 따라 MariaDB 사본에서 먼저 적용/기동을 검증한다. Flyway가 꺼진 환경에서는 새 앱을 먼저 기동해 Hibernate가 테이블을 생성하기 전에 승인된 배포 절차로 마이그레이션을 적용해야 SQL의 소유자 FK와 조회 인덱스까지 확보할 수 있다. 신규 기록이 생긴 뒤 앱을 롤백하더라도 테이블과 업로드 파일은 보존한다.

운영 적용 전에 별도로 수행할 항목: 실제 MariaDB/Flyway 배포 리허설, 운영 지도 타일/MinIO 연결 확인. 이 개발 검증은 운영 배포나 운영 인프라 검증을 대신하지 않는다.
