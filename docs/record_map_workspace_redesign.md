# 기록 지도 작업 공간 개편 · 2026-10-13

## 목표와 구현

기존 여행·경로·예산·공유 기능은 그대로 두고, 기록 지도에서 검색·장소/모음/일상 기록 목록·지도 조절·재생을 하나의 지도 안에서 사용한다.

- 데스크톱은 접을 수 있는 340px 왼쪽 검색/목록, 오른쪽 소형 도구 모음, 하단 재생 바다. 지도 밖의 큰 조회 조건/조절 박스와 별도 목록 화면 전환을 제거했다.
- 모바일은 접힌 검색 줄과 아래쪽에서 펼치는 목록 패널이다. 목록을 펼치면 지도 도구 모음을 잠시 숨겨 겹침을 방지하고, 추가·관리 메뉴는 목록 헤더로 이동한다. 목록을 접으면 도구 모음으로 돌아온다.
- 전체화면에도 같은 검색·목록·등록 기능이 남는다. 앱의 테마 전환/펫 오버레이는 이 기록 지도 전체화면에서만 숨기며, 닫으면 원래 상태로 돌아온다. 기존 여행 지도 기본 옵션/화면은 변경하지 않았다.
- 저장 장소·지역·장소 메모·방문 제목/메모는 서버 검색이다. 화면의 현재 페이지뿐 아니라 해당 소유자/모음의 전체 저장 자료를 대상으로 조회한다. 검색어는 최대 100자이고 `%`, `_`, `!`는 LIKE 와일드카드가 아닌 문자로 처리한다.
- 목록과 핀을 양방향 선택한다. 목록 선택은 적정 확대(15)로 이동하고 핀에 간단한 사진/정보 팝업을 열며, 핀 선택은 해당 목록 항목을 강조한다. 현재 페이지에 없는 지도 장소는 선택한 장소 카드로 표시한다. 지도 이동은 목록/도구/재생 바를 제외한 가시 영역을 기준으로 한다.
- 모음은 색상, 전체 장소 수, 유효한 공유 링크 여부를 표시한다. 장소 상세·사진 확대·편집/삭제 확인 팝업은 유지한다.
- 기록 재생은 날짜·일시정지/재개·1~5초 간격·날짜 전환 안내를 유지한다. 날짜 없는 북마크는 재생하지 않는다.

## 조회/권한과 상한

- 목록: `GET /api/record-map/overview?q=&collectionId=&state=&from=&to=&page=&size=`. 기존 호출의 기본 크기 100은 유지하고 새 화면은 30개씩 조회한다.
- 지도: `GET /api/record-map/map`에 동일한 검색/필터를 적용한다. 목록 페이지 변경은 지도 조회/카메라/재생을 초기화하지 않는다. 지도는 최근 장소 최대 500개, 방문 200건, 연결 여행 사진 1,000개를 유지하며 제한에 걸리면 안내를 표시한다. 선택한 목록 장소가 지도 상한 밖이면 그 한 장소도 선택 상태로 추가 표시한다.
- 공개 지도: `GET /api/record-map/public/{token}`과 `/map`. 매 요청에서 유효한 링크와 모음 범위를 검사한다. 기본 장소-only 공유는 비공개 메모·방문 제목/메모를 검색 조건으로도 사용하지 않아 숨겨진 자료의 존재/개수를 추론할 수 없다. 사진·방문 공유를 선택한 경우에만 공개된 기록 검색과 날짜 필터를 제공한다.
- 공유 링크가 만료/취소돼 새 요청이 거부되면 지도·목록·열린 상세/사진을 함께 비운다. 소유자의 다른 모음 수나 공유 상태를 공개 응답에 넣지 않는다.

## 명시적 새 위치 검색

새 위치 찾기는 등록하지 않은 주소/지역을 찾는 별도 모드다. 입력 중 자동완성 요청은 보내지 않고 검색 버튼/Enter로 실행한다. 결과 선택은 임시 위치 표시이며 저장 버튼을 눌러 등록 폼을 확인해야 저장된다.

- 인증된 `GET /api/record-map/locations/search?q=`를 통해 서버에서 요청한다. 새 기록 지도와 그 장소 등록창은 직접 외부 API를 호출하지 않는다. 공유 지도에는 이 등록용 검색을 제공하지 않는다.
- 기존 `app.travel.reverse-geocode-base-url`의 `/reverse` 경로에서 `/search` 경로를 파생해 Nominatim-compatible 공급자를 사용한다. 기존 User-Agent/요청 간격 설정을 재사용하고 URL/키는 응답에 노출하지 않는다.
- 기존 역지오코딩과 동일한 `geocode-provider:{host}` DB 예약 키를 사용해 여러 서버의 요청 시작 간격을 공유한다. 최소 1초(기본 1.2초), 동시 외부 검색 1개, 캐시 최대 256개/24시간, 결과 최대 6개, 응답 최대 64KiB, 연결 3초/읽기 5초다. 예약 저장소가 불가하면 외부 요청을 보내지 않는다.
- 입력한 주소/지역만 전달한다. 저장한 기록·메모·사용자 ID·공유 토큰은 전달하지 않는다. 공급자 오류는 일반 메시지로 변환한다.
- OSM 출처와 [Nominatim 사용 정책](https://operations.osmfoundation.org/policies/nominatim/)을 표시한다. 공용 API의 사용량/식별/라이선스 정책은 운영에서도 준수해야 한다. 기존 여행 화면의 브라우저 직통 위치 검색은 이번 개편의 기본 동작 보존 범위여서 별도 정책 점검 대상이다.

## 검증

- 격리 H2 및 로컬 모의 위치 서버에서 여행/기록 지도/개인정보 회귀 82개 통과(오류·실패 0).
- 프런트 단위 테스트 22개 통과, 프로덕션 빌드 통과.
- 새 기록 지도 22개 + 기존 여행 지도 44개 = 브라우저 회귀 66개 통과. 데스크톱 1440×900, FHD 1920×1080, 모바일 390×844/360×640, 전체화면을 확인했다. 가상 API/사진으로 실행하고 실제 외부 지도/위치 네트워크는 차단했다.
- 추가 최종 스크린샷 점검에서 목록 자동 접힘이 확대 요청을 덮어쓰지 않도록 수정하고, 목적지 확대 15/전체화면 유지·위치 확인 후 저장 등 집중 시나리오 6개를 재검증했다.
- 실제 H2 검증은 516개 장소의 전체 검색/페이지 분리/지도 상한, 타 사용자 격리, 비공개 공유 메모 검색 차단과 와일드카드 처리까지 포함한다. 위치 제공자 검증은 로컬 HTTP 모의 서버로 캐시·공유 예약·입력/좌표/결과/응답 제한과 오류 처리를 확인한다.
