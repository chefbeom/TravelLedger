# 기록 지도 작업 공간 개편 · 2026-10-13

## 목표와 구현

기존 여행·경로·예산·공유 기능은 그대로 두고, 기록 지도에서 검색·장소/모음/일상 기록 목록·지도 조절을 하나의 지도 안에서 사용한다. 여정 재생은 기존 여행 지도에서만 제공한다.

- 데스크톱은 접을 수 있는 340px 왼쪽 검색/목록과 오른쪽 소형 도구 모음이다. 지도 밖의 큰 조회 조건/조절 박스와 별도 목록 화면 전환을 제거했다.
- 모바일은 접힌 검색 줄과 아래쪽에서 펼치는 목록 패널이다. 목록을 펼치면 지도 도구 모음을 잠시 숨겨 겹침을 방지하고, 추가·관리 메뉴는 목록 헤더로 이동한다. 목록을 접으면 도구 모음으로 돌아온다.
- 전체화면에도 같은 검색·목록·등록 기능이 남는다. 앱의 테마 전환/펫 오버레이는 이 기록 지도 전체화면에서만 숨기며, 닫으면 원래 상태로 돌아온다. 기존 여행 지도 기본 옵션/화면은 변경하지 않았다.
- 저장 장소·지역·장소 메모·방문 제목/메모는 서버 검색이다. 화면의 현재 페이지뿐 아니라 해당 소유자/모음의 전체 저장 자료를 대상으로 조회한다. 검색어는 최대 100자이고 `%`, `_`, `!`는 LIKE 와일드카드가 아닌 문자로 처리한다.
- 목록과 핀을 양방향 선택한다. 목록 선택은 적정 확대(15)로 이동하고 핀에 간단한 사진/정보 팝업을 열며, 핀 선택은 해당 목록 항목을 강조한다. 현재 페이지에 없는 지도 장소는 선택한 장소 카드로 표시한다. 지도 이동은 목록/도구를 제외한 가시 영역을 기준으로 한다.
- 모음은 색상, 전체 장소 수, 유효한 공유 링크 여부를 표시한다. 장소 상세·사진 확대·편집/삭제 확인 팝업은 유지한다.
- 기록 지도의 재생 UI·실행·타이머 연결은 제거했다. 기존 여행 지도의 날짜별 재생·일시정지/재개·1~5초 간격·날짜 전환은 유지한다.

## 조회/권한과 상한

- 목록: `GET /api/record-map/overview?q=&collectionId=&state=&from=&to=&page=&size=`. 기존 호출의 기본 크기 100은 유지하고 새 화면은 30개씩 조회한다.
- 지도: `GET /api/record-map/map`에 동일한 검색/필터를 적용한다. 목록 페이지 변경은 지도 조회/카메라/재생을 초기화하지 않는다. 지도는 최근 장소 최대 500개, 방문 200건, 연결 여행 사진 1,000개를 유지하며 제한에 걸리면 안내를 표시한다. 선택한 목록 장소가 지도 상한 밖이면 그 한 장소도 선택 상태로 추가 표시한다.
- 공개 지도: `GET /api/record-map/public/{token}`과 `/map`. 매 요청에서 유효한 링크와 모음 범위를 검사한다. 기본 장소-only 공유는 비공개 메모·방문 제목/메모를 검색 조건으로도 사용하지 않아 숨겨진 자료의 존재/개수를 추론할 수 없다. 사진·방문 공유를 선택한 경우에만 공개된 기록 검색과 날짜 필터를 제공한다.
- 공유 링크가 만료/취소돼 새 요청이 거부되면 지도·목록·열린 상세/사진을 함께 비운다. 소유자의 다른 모음 수나 공유 상태를 공개 응답에 넣지 않는다.

## 명시적 새 위치 검색

새 위치 찾기는 등록하지 않은 주소/지역을 찾는 별도 모드다. 입력 중 자동완성 요청은 보내지 않고 검색 버튼/Enter로 실행한다. 결과 선택은 임시 위치 표시이며 저장 버튼을 눌러 등록 폼을 확인해야 저장된다.

- 인증된 `GET /api/record-map/locations/search?q=`를 통해 서버에서 요청한다. 새 기록 지도와 그 장소 등록창은 직접 외부 API를 호출하지 않는다. 공유 지도에는 이 등록용 검색을 제공하지 않는다.
- 기존 `app.travel.reverse-geocode-base-url`의 `/reverse` 경로에서 `/search` 경로를 파생해 Nominatim-compatible 공급자를 사용한다. 기존 User-Agent/요청 간격 설정을 재사용하고 URL/키는 응답에 노출하지 않는다.
- 기존 역지오코딩과 동일한 `geocode-provider:{host}` DB 예약 키를 사용해 여러 서버의 요청 시작 간격을 공유한다. 최소 1초(기본 1.2초), 동시 외부 검색 1개, 캐시 최대 256개/24시간, 결과 최대 10개, 응답 최대 64KiB, 연결 3초/읽기 5초다. 예약 저장소가 불가하면 외부 요청을 보내지 않는다.
- 입력한 주소/지역만 전달한다. 저장한 기록·메모·사용자 ID·공유 토큰은 전달하지 않는다. 공급자 오류는 일반 메시지로 변환한다.
- OSM 출처와 [Nominatim 사용 정책](https://operations.osmfoundation.org/policies/nominatim/)을 표시한다. 공용 API의 사용량/식별/라이선스 정책은 운영에서도 준수해야 한다. 기존 여행 화면의 브라우저 직통 위치 검색은 이번 개편의 기본 동작 보존 범위여서 별도 정책 점검 대상이다.

## 초기 개편 검증

## 후속 수정 · 재생 분리와 검색 위치/연관 후보

- 기록 지도에는 재생 기능을 노출하지 않는다. 방문 날짜·사진 조회와 기존 여행 지도 재생은 유지한다.
- 지도 타일 색상은 여행 지도와 공통 light/dark 토큰을 사용한다. 기록 지도·위치 등록창·공유 기록 지도도 같은 설정을 상속한다.
- 검색 즉시 최대 10개 후보를 번호 핀으로 표시하고 첫 후보로 이동해 이름·주소·좌표 팝업을 연다. 가까운 후보가 저장된 사진 클러스터에 합쳐지지 않도록 분리하고, 선택한 후보를 위에 표시한다. 후보 핀은 임시 표시이며 확인 폼에서 저장하기 전에는 DB에 등록하지 않는다.
- 작은 모바일은 검색 후 목록을 접어 위치를 보여주고 `후보 N` 버튼으로 목록을 다시 연다. 기록 지도에서만 헤더를 압축해 360px 화면의 지도 공간을 확보했다.
- Nominatim 검색에 `namedetails=1`, `entrances=1`을 요청한다. 실제 반환된 출입구 이름/번호·좌표만 후보로 추가하고, 중복·범위 밖 좌표·비공개/서비스 출입구를 제외한다. 출입구가 없는 응답에서 출구 위치를 생성하거나 역 중심 좌표로 대신하지 않는다. 제공자가 이 옵션/데이터를 지원하지 않으면 일반 장소 후보만 표시된다. [검색 API](https://nominatim.org/release-docs/latest/api/Search/), [출입구 응답 형식](https://nominatim.org/release-docs/latest/api/Output/#entrances).
- `우장산역 → 우장산역 출구`는 사용자가 눌러 실행하는 검색어 좁히기다. 입력 중 연관 추천은 이번 화면에서 이미 조회한 후보 최대 40개만 메모리에 보관해 최대 5개로 필터링한다. 외부 API에 자동완성 요청을 보내거나 저장된 메모를 전송하지 않는다. 화면 종료·공유 범위 전환 시 메모리 후보를 비우고, 취소한 이전 응답은 화면을 덮어쓰지 못한다. [Nominatim 공용 서버 정책](https://operations.osmfoundation.org/policies/nominatim/).
- 사용자 선택에 따라 카카오 Local이나 새 API 키는 추가하지 않았다. 국내 출구·상호 검색의 완전성은 기존 공급자의 데이터 범위에 한정된다.

후속 검증 설정은 `frontend/playwright.record-map-search-fixes.config.js`다. 루프백 5193 포트와 별도 산출물 폴더를 사용하며 운영 DB/API를 사용하지 않는다.
