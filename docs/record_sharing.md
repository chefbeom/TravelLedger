# 승인 기반 기록 공유

가계부의 `기록 공유`와 여행의 `공유받은 여행`에서 받은/보낸 요청, 상태 필터, 10건 단위 페이지를 확인한다. 승인 대기 숫자는 화면 진입, 창 포커스 복귀 및 60초 간격으로 갱신한다.

## 그룹

기존 `travel_share_groups`와 멤버 목록을 재사용한다. 그룹 소유자도 멤버로 취급하고, 같은 그룹의 활성 사용자끼리 요청을 보낼 수 있다. 기존 여행 공유 그룹의 멤버에게도 기록 공유 화면에 그 그룹이 보인다. 그룹 소유자만 멤버 수정·그룹 삭제를 할 수 있다. 공유 그룹 관리에서 가족·친구·모임 그룹을 만들 수 있다.

화면은 `저장된 공유 그룹`과 `새 공유 그룹 만들기`/`그룹 멤버 수정`으로 구분한다. 저장된 그룹에는 멤버 이름·아이디, 본인 여부, 관리자/멤버 역할, 수정 가능 여부를 표시한다. 검색 결과의 `추가`는 아직 저장하지 않은 멤버 선택이며, `그룹 저장`을 눌러야 반영된다. 그룹 저장 자체는 기록을 공유하지 않는다. 기존 본인 그룹과 같은 이름으로 새 그룹을 만들어 멤버를 실수로 덮어쓰지 않도록, 기존 그룹의 `멤버 수정`을 안내한다.

공유 대화상자의 받는 사람은 기본적으로 아무도 선택하지 않는다. 개별 선택 또는 명시적인 `전체 선택`을 사용할 수 있고, 선택 인원과 아이디를 확인한 후 요청한다. 그룹을 바꾸면 이전 선택은 초기화하며, 본인은 대상에서 제외한다. 한 번에 최대 50명에게 요청할 수 있다.

## 가계부

- 빠른 거래 입력은 기본적으로 `거래 등록`/`거래 수정`만 표시한다. 작성한 내역은 날짜별 거래 시트의 `공유` 버튼으로 공유한다. `수정`·`공유`·`삭제` 작업은 모두 표시되며, 데스크톱의 가로 스크롤에서도 작업 열을 고정한다.
- 빠른 거래 입력의 `입력 설정` → `등록 후 공유 버튼 표시`를 켜면 기존 `등록 후 공유`/`수정 후 공유` 버튼도 사용할 수 있다. 계정별 달력 보기 설정(`household-calendar-view`의 `shareAfterSaveEnabled`, 기본 `false`)으로 로컬·서버에 저장한다. 켜기만 해서는 공유하지 않으며, 버튼을 눌러 저장한 뒤 별도 대상 선택을 거쳐야 한다.
- 공유할 때는 요청과 그 시점의 스냅샷만 저장한다. 원본 이후 변경이 승인 대기 스냅샷을 바꾸지 않는다.
- 거래 공유 창의 `공유 메모 (선택)`에 최대 500자까지 입력할 수 있다. 선택한 받는 사람에게 동일한 메모를 전달하며, 받은 기록·보낸 기록·승인 전 확인 창에서 줄바꿈을 유지한 텍스트로 표시한다. 거래의 기존 `memo`와 별도인 `shareMemo`로 저장하고, 승인 시 거래 메모에 자동으로 합치거나 복사하지 않는다. 빈 입력은 `null`로 저장한다. 전송 실패 시 작성 중인 메모와 수신자 선택을 유지한다.
- 수신자가 `확인 후 내 가계부에 기록`을 눌러 제목·금액·날짜·메모·분류·결제수단을 검토/수정한 뒤 승인한다. 분류와 결제수단은 반드시 받는 사람 소유의 값을 사용한다. 송신자의 여행 연결 ID는 복사하지 않는다.
- 승인 시 독립 거래를 하나 생성한다. 이후 양쪽의 수정/삭제는 서로 영향을 주지 않는다. `record_shares.source_id`, `sender_id`, `imported_ledger_entry_id`가 출처를 기록한다.
- 동일 원본·수신자는 그룹이 달라도 한 번만 가져온다. 요청 생성 시 원본을 잠그고, 재공유·승인은 동일 요청 행을 잠근 뒤 최신 상태를 확인한다. DB 고유 제약과 함께 중복 클릭·재시도 및 승인/재공유 동시 실행에 의한 중복 생성을 방지한다. 이미 승인한 요청의 재시도는 기존 결과를 반환한다.
- 같은 그룹의 대기 요청을 반복 전송해도 기존 스냅샷과 공유 메모를 덮어쓰지 않는다. 대기 요청의 메모를 바꾸려면 기존 요청을 취소한 뒤 다시 공유한다. 거절/취소 후 새 요청을 보내면 새 메모로 교체하며, 새 메모가 없으면 이전 메모를 비운다. 이미 가져온 거래의 공유 메모는 재공유로 바뀌지 않는다.
- 승인 대기 중 원본이 삭제되거나 어느 한쪽이 그룹에서 빠지면 승인할 수 없다. 이미 가져온 가계부 거래는 그룹/원본 삭제 후에도 남는다.
- 현재 그룹에서 송신자가 빠지거나 비활성화되면 요청 목록과 대기 알림에서 제외한다. 수신자가 탈퇴한 그룹의 요청도 조회하지 않는다.

## 여행

- 본인 여행 선택 후 `그룹에 여행 공유`를 누른다. 예정/완성 여행 모두 요청할 수 있다.
- 수신자가 수락하면 `공유받은 여행`에서 기존 여행 전시 컴포넌트로 사진·지도·기록·경로와 여행 상세를 읽기 전용으로 본다. 여행을 복제하거나 소유자 변경/수정 권한을 부여하지 않는다.
- 원본 변경은 열람 시 반영된다. 송신자의 공유 취소, 그룹 삭제/멤버 제거, 원본 여행 삭제 시 열람이 종료된다.
- 여행 상세뿐 아니라 각 사진/썸네일 요청마다 수신자·수락 상태·현재 양쪽 그룹 소속을 검사한다. 인증된 사진 응답은 `private, no-store`로 반환한다. 기존 공개 지도 URL과 별도 경로이며 공개 토큰을 만들지 않는다.
- 기존 그룹 접근이 끝난 여행을 다른 그룹에서 다시 공유하면 새로 수락해야 한다. 이미 가져온 가계부의 중복 생성 방지와는 별도 정책이다.

## 여행 지도 확대와 Esc

사진 지도(개인 지도·공개 여행·공유 지도)의 `전체 화면`은 브라우저 안의 가용 화면을 채우는 앱 확대 화면이다. 브라우저 주소창은 유지한다. 브라우저 자체 전체화면은 Esc가 사이트의 `preventDefault`와 별개로 종료될 수 있으므로, 별도 Keyboard Lock 권한을 요구하지 않고 닫기 순서를 제어한다([Fullscreen API 안내](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API/Guide), [Keyboard Lock의 Esc 제어와 권한](https://developer.chrome.com/docs/capabilities/web-apis/keyboard-lock)). 여행 계획/경로 편집 지도의 기존 브라우저 전체화면 기능은 변경하지 않는다.

- 사진 상세가 열려 있으면 첫 Esc는 상세만 닫는다. 핀의 작은 카드와 플로팅 미리보기, 확대 지도는 유지된다.
- 다음 Esc는 미리보기·핀 카드를 닫는다. 선택된 장소 정보만 남아 있으면 그 정보부터 닫는다.
- 사진/정보 창이 모두 닫힌 상태에서 Esc를 누르거나 `전체 화면 종료`를 누르면 원래 지도 크기로 돌아간다.
- Esc를 길게 눌러 발생하는 반복 입력은 무시해 여러 겹이 동시에 닫히지 않게 한다. 확대 화면의 Tab 포커스는 해당 지도/사진 상세 안에서만 이동하며, 종료하면 버튼 포커스와 페이지 스크롤 위치를 복원한다. 탭 전환·컴포넌트 제거 시 배경 스크롤 잠금도 해제한다.

## 지도 사진 미리보기 크기 조절

왼쪽 플로팅 사진 미리보기는 데스크톱에서 오른쪽 아래 모서리, 모바일에서 오른쪽 위 모서리의 조절 손잡이를 드래그하여 너비·높이를 바꾼다. 마우스와 터치를 모두 지원하며, 손잡이에 키보드 포커스를 두면 방향키로 16px씩 조절하고 Home 또는 `기본 크기` 버튼으로 초기화할 수 있다. 핀에 붙는 작은 썸네일·정보 카드는 기존 크기를 유지한다.

- 조절한 크기는 현재 지도에서 사진을 넘기거나 여정을 바꾸거나 미리보기를 닫았다 다시 열어도 유지한다. 새로고침·지도 컴포넌트 재생성 이후까지 저장하는 설정은 아니다.
- 데스크톱 너비는 지도 내부 너비의 60% 이내·최대 960px로 제한하고, 모바일은 지도 내부 너비 이내로 제한한다. 높이도 화면 안에 들어오도록 제한한다. 창을 줄이면 표시 크기만 자동 축소하고, 다시 늘리면 사용자가 정한 크기를 복원한다.
- 기본 미리보기도 기존보다 넓게 표시하고, 조절한 너비가 480px를 넘으면 더 큰 썸네일을 요청한다. 사진은 비율을 유지하며, 썸네일 실패 시 기존 원본/대체 표시 처리를 유지한다.
- 크기 조절 중 지도를 끌거나 사진 상세를 열지 않도록 이벤트를 분리한다. 미리보기 닫기·탭 전환·지도 제거 시 드래그 상태를 정리한다. 전체 화면이 아닌 지도와 개인·공유 지도에서 같은 방식을 사용한다.

## API / 운영

- `/api/record-shares/groups`: 접근 가능한 그룹/멤버 목록.
- `/api/record-shares/counts`: 가계부/여행 승인 대기 숫자.
- `GET /api/record-shares?kind=LEDGER|TRAVEL&sent=false|true&status=PENDING|ACCEPTED|REJECTED|CANCELED&page=0&size=10`: 접근 가능한 그룹의 기록만 조회.
- `POST /api/record-shares`: `groupId`, `kind`, `sourceId`, `recipientIds`(최대 50명), 선택 `shareMemo`(최대 500자). 목록·생성·응답 DTO에도 `shareMemo`를 반환한다. 필드를 생략하는 기존 클라이언트 요청도 허용한다.
- `POST /api/record-shares/{id}/accept-ledger`: 기존 LedgerEntryRequest 형식, 받는 사람 소유 분류 사용.
- `POST /api/record-shares/{id}/accept-travel`, `/reject`, `/cancel`.
- `GET /api/record-shares/{id}/travel`: 수락한 여행 상세.
- `GET /api/travel/record-shares/{id}/media/{mediaId}/content`: 수락한 여행의 원본/썸네일.

모든 API는 기존 세션 인증과 CSRF 보호를 적용한다. 다른 수신자/그룹/원본 ID를 사용한 접근은 허용하지 않는다. 데이터/자격증명은 로그에 추가하지 않는다.

배포 시 `V20261003_030__record_sharing.sql` 마이그레이션이 적용돼야 한다. 기존 여행 직접 공유/공개 전시 기능은 유지되며, 신규 승인 방식은 기록 공유 화면에서 사용한다. 운영 DB에 수동 데이터를 삽입하거나 기존 공유를 일괄 승인하지 않는다.

공유 메모 기능은 추가 마이그레이션 `V20261003_031__record_share_memo.sql`로 `record_shares.share_memo VARCHAR(500) NULL` 컬럼을 생성한다. 기존 공유 기록과 거래 스냅샷은 변경하지 않으며 기존 행의 메모는 `NULL`이다. 프론트·백엔드·DB 마이그레이션을 함께 배포해야 새 메모를 저장할 수 있다. 운영 DB에 직접 변경을 실행하지 않았다.
