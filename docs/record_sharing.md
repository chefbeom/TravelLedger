# 승인 기반 기록 공유

가계부의 `기록 공유`와 여행의 `공유받은 여행`에서 받은/보낸 요청, 상태 필터, 10건 단위 페이지를 확인한다. 승인 대기 숫자는 화면 진입, 창 포커스 복귀 및 60초 간격으로 갱신한다.

## 그룹

기존 `travel_share_groups`와 멤버 목록을 재사용한다. 그룹 소유자도 멤버로 취급하고, 같은 그룹의 활성 사용자끼리 요청을 보낼 수 있다. 기존 여행 공유 그룹의 멤버에게도 기록 공유 화면에 그 그룹이 보인다. 그룹 소유자만 멤버 수정·그룹 삭제를 할 수 있다. 공유 그룹 관리에서 가족·친구·모임 그룹을 만들 수 있다.

## 가계부

- 빠른 거래 입력의 `등록 후 공유`/`수정 후 공유`, 날짜별 거래 시트의 `공유` 버튼으로 그룹과 받는 사람을 선택한다.
- 공유할 때는 요청과 그 시점의 스냅샷만 저장한다. 원본 이후 변경이 승인 대기 스냅샷을 바꾸지 않는다.
- 수신자가 `확인 후 내 가계부에 기록`을 눌러 제목·금액·날짜·메모·분류·결제수단을 검토/수정한 뒤 승인한다. 분류와 결제수단은 반드시 받는 사람 소유의 값을 사용한다. 송신자의 여행 연결 ID는 복사하지 않는다.
- 승인 시 독립 거래를 하나 생성한다. 이후 양쪽의 수정/삭제는 서로 영향을 주지 않는다. `record_shares.source_id`, `sender_id`, `imported_ledger_entry_id`가 출처를 기록한다.
- 동일 원본·수신자는 그룹이 달라도 한 번만 가져온다. 요청 생성 시 원본을 잠그고, 재공유·승인은 동일 요청 행을 잠근 뒤 최신 상태를 확인한다. DB 고유 제약과 함께 중복 클릭·재시도 및 승인/재공유 동시 실행에 의한 중복 생성을 방지한다. 이미 승인한 요청의 재시도는 기존 결과를 반환한다.
- 승인 대기 중 원본이 삭제되거나 어느 한쪽이 그룹에서 빠지면 승인할 수 없다. 이미 가져온 가계부 거래는 그룹/원본 삭제 후에도 남는다.
- 현재 그룹에서 송신자가 빠지거나 비활성화되면 요청 목록과 대기 알림에서 제외한다. 수신자가 탈퇴한 그룹의 요청도 조회하지 않는다.

## 여행

- 본인 여행 선택 후 `그룹에 여행 공유`를 누른다. 예정/완성 여행 모두 요청할 수 있다.
- 수신자가 수락하면 `공유받은 여행`에서 기존 여행 전시 컴포넌트로 사진·지도·기록·경로와 여행 상세를 읽기 전용으로 본다. 여행을 복제하거나 소유자 변경/수정 권한을 부여하지 않는다.
- 원본 변경은 열람 시 반영된다. 송신자의 공유 취소, 그룹 삭제/멤버 제거, 원본 여행 삭제 시 열람이 종료된다.
- 여행 상세뿐 아니라 각 사진/썸네일 요청마다 수신자·수락 상태·현재 양쪽 그룹 소속을 검사한다. 인증된 사진 응답은 `private, no-store`로 반환한다. 기존 공개 지도 URL과 별도 경로이며 공개 토큰을 만들지 않는다.
- 기존 그룹 접근이 끝난 여행을 다른 그룹에서 다시 공유하면 새로 수락해야 한다. 이미 가져온 가계부의 중복 생성 방지와는 별도 정책이다.

## API / 운영

- `/api/record-shares/groups`: 접근 가능한 그룹/멤버 목록.
- `/api/record-shares/counts`: 가계부/여행 승인 대기 숫자.
- `GET /api/record-shares?kind=LEDGER|TRAVEL&sent=false|true&status=PENDING|ACCEPTED|REJECTED|CANCELED&page=0&size=10`: 접근 가능한 그룹의 기록만 조회.
- `POST /api/record-shares`: `groupId`, `kind`, `sourceId`, `recipientIds`(최대 50명).
- `POST /api/record-shares/{id}/accept-ledger`: 기존 LedgerEntryRequest 형식, 받는 사람 소유 분류 사용.
- `POST /api/record-shares/{id}/accept-travel`, `/reject`, `/cancel`.
- `GET /api/record-shares/{id}/travel`: 수락한 여행 상세.
- `GET /api/travel/record-shares/{id}/media/{mediaId}/content`: 수락한 여행의 원본/썸네일.

모든 API는 기존 세션 인증과 CSRF 보호를 적용한다. 다른 수신자/그룹/원본 ID를 사용한 접근은 허용하지 않는다. 데이터/자격증명은 로그에 추가하지 않는다.

배포 시 `V20261003_030__record_sharing.sql` 마이그레이션이 적용돼야 한다. 기존 여행 직접 공유/공개 전시 기능은 유지되며, 신규 승인 방식은 기록 공유 화면에서 사용한다. 운영 DB에 수동 데이터를 삽입하거나 기존 공유를 일괄 승인하지 않는다.

운영 DB·파일 저장소 변경이나 배포는 이 검증에 포함되지 않는다. 운영 적용 전 DB 백업 후 기존 배포 절차로 마이그레이션 적용 여부를 확인하고, 두 테스트 계정으로 요청→승인→독립 수정 및 여행 공유 취소를 확인한다.
